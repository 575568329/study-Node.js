# 事务处理

## 📚 核心概念

**事务**：一组SQL操作，要么**全部成功**，要么**全部失败**。

---

## 🎓 为什么需要事务？

### ❌ 没有事务的问题（危险！）

```javascript
// A转账100元给B

// 步骤1：A账户 -100
UPDATE accounts SET balance = balance - 100 WHERE id = 1;  // 成功
// 此时：A = 900元

// 步骤2：B账户 +100
UPDATE accounts SET balance = balance + 100 WHERE id = 2;  // 失败！（数据库断电）
// 此时：B = 0元

// 结果：A少了100元，B没收到钱 → **钱消失了！** 💸
```

---

### ✅ 使用事务（安全！）

```javascript
START TRANSACTION;  // 开始事务

  // 步骤1：A账户 -100
  UPDATE accounts SET balance = balance - 100 WHERE id = 1;  // 成功

  // 步骤2：B账户 +100
  UPDATE accounts SET balance = balance + 100 WHERE id = 2;  // 失败！

COMMIT;  // 提交事务（不会执行，因为步骤2失败）

ROLLBACK;  // 回滚事务（撤销步骤1的修改）

// 结果：A还是1000元，B还是0元 → **钱没有消失** ✅
```

---

## 💡 事务的ACID特性

### A - 原子性（Atomicity）
**要么全部成功，要么全部失败**

```javascript
转账示例：
步骤1：A -100 ✅
步骤2：B +100 ❌ 失败
结果：全部回滚，A的钱没有扣 ✅
```

### C - 一致性（Consistency）
**数据始终保持一致**

```javascript
转账前：A + B = 1000 + 0 = 1000元
转账后：A + B = 900 + 100 = 1000元 ✅
总金额不变！
```

### I - 隔离性（Isolation）
**多个事务之间互不干扰**

```javascript
用户1：A转账给B（同时进行）
用户2：A转账给C（同时进行）

每个事务独立执行，不会互相影响 ✅
```

### D - 持久性（Durability）
**事务提交后，永久保存**

```javascript
COMMIT后，即使断电，数据也不会丢失 ✅
```

## 🔧 MySQL事务操作

### 基本语法

```sql
-- 开始事务
START TRANSACTION;

-- 执行SQL
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

-- 提交事务（全部成功）
COMMIT;

-- 或回滚事务（有失败）
ROLLBACK;
```

## 💻 Node.js中实现事务

### ❌ 错误的写法（没有事务）

```javascript
const transfer = async (fromId, toId, amount) => {
  // 步骤1：扣款
  await pool.query(
    'UPDATE accounts SET balance = balance - ? WHERE id = ?',
    [amount, fromId]
  );

  // ⚠️ 如果这里出错（断电、程序崩溃），钱已经扣了，但没到账！

  // 步骤2：收款
  await pool.query(
    'UPDATE accounts SET balance = balance + ? WHERE id = ?',
    [amount, toId]
  );
};
```

---

### ✅ 正确的写法（使用事务）

```javascript
const transfer = async (fromId, toId, amount) => {
  const connection = await pool.promise().getConnection();

  try {
    // 开始事务
    await connection.beginTransaction();

    // 步骤1：扣款
    await connection.query(
      'UPDATE accounts SET balance = balance - ? WHERE id = ?',
      [amount, fromId]
    );

    // 步骤2：收款
    await connection.query(
      'UPDATE accounts SET balance = balance + ? WHERE id = ?',
      [amount, toId]
    );

    // 提交事务（全部成功）
    await connection.commit();

    console.log('转账成功');
  } catch (error) {
    // 回滚事务（有错误，全部撤销）
    await connection.rollback();

    console.log('转账失败，已回滚');
    throw error;
  } finally {
    // 释放连接回连接池
    connection.release();
  }
};
```

## 🎯 实战案例：完整的转账API

```javascript
// routes/transfer.js
router.post('/transfer', authMiddleware, async (req, res, next) => {
  const connection = await pool.promise().getConnection();

  try {
    const { toUserId, amount } = req.body;
    const fromUserId = req.user.user_id;

    // 开始事务
    await connection.beginTransaction();

    // 1. 检查转账用户余额
    const [users] = await connection.query(
      'SELECT balance FROM users WHERE id = ?',
      [fromUserId]
    );

    if (users.length === 0) {
      await connection.rollback();
      return res.status(404).json({ message: '用户不存在' });
    }

    if (users[0].balance < amount) {
      await connection.rollback();
      return res.status(400).json({ message: '余额不足' });
    }

    // 2. 检查收款用户是否存在
    const [targetUsers] = await connection.query(
      'SELECT id FROM users WHERE id = ?',
      [toUserId]
    );

    if (targetUsers.length === 0) {
      await connection.rollback();
      return res.status(404).json({ message: '收款用户不存在' });
    }

    // 3. 扣款
    await connection.query(
      'UPDATE users SET balance = balance - ? WHERE id = ?',
      [amount, fromUserId]
    );

    // 4. 收款
    await connection.query(
      'UPDATE users SET balance = balance + ? WHERE id = ?',
      [amount, toUserId]
    );

    // 5. 记录转账日志
    await connection.query(
      'INSERT INTO transfers (from_user_id, to_user_id, amount, created_at) VALUES (?, ?, ?, NOW())',
      [fromUserId, toUserId, amount]
    );

    // 提交事务
    await connection.commit();

    res.json({
      success: true,
      message: '转账成功'
    });
  } catch (error) {
    // 回滚事务
    await connection.rollback();
    next(error);
  } finally {
    connection.release();
  }
});
```

## 📝 事务的应用场景

### 1️⃣ 银行转账
```javascript
START TRANSACTION;
  UPDATE accounts SET balance = balance - 100 WHERE id = 1;
  UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;
```

### 2️⃣ 发布文章
```javascript
START TRANSACTION;

COMMIT;
```


## 🤔 常见问题

### Q1: 什么时候需要使用事务？
**A**:
- ✅ 多个SQL操作必须同时成功时
- ✅ 涉及金钱交易时
- ✅ 需要保持数据一致性时

### Q2: 为什么需要 `connection.release()`？
**A**:
- 不是"释放事务"（事务通过 ROLLBACK/COMMIT 结束）
- 是**释放数据库连接**回连接池
- 让其他请求可以使用这个连接

**类比**：
- 连接池 = 自行车出租站
- `getConnection()` = 租一辆自行车
- `release()` = **还车**（不是销毁自行车）

### Q3: 事务会影响性能吗？
**A**:
- ✅ 轻微影响（锁定资源）
- ✅ 但保证了数据安全（值得！）
- ✅ 事务要尽量短（不要长时间占用）

## 🎯 最佳实践

1. ✅ **涉及多个表操作时使用事务**
   ```javascript
   START TRANSACTION;
     // 多个操作
   COMMIT;
   ```

2. ✅ **始终使用 try-catch-finally**
   ```javascript
   try {
     await connection.beginTransaction();
     // 操作
     await connection.commit();
   } catch (error) {
     await connection.rollback();
     throw error;
   } finally {
     connection.release();
   }
   ```

3. ✅ **事务要尽量短**
   ```javascript
   // ❌ 不好：事务中有复杂计算
   START TRANSACTION;
     UPDATE accounts SET balance = ...;
     const result = complexCalculation();  // 耗时
     UPDATE accounts SET balance = ...;
   COMMIT;

   // ✅ 好：复杂计算在事务外
   const result = complexCalculation();  // 先计算
   START TRANSACTION;
     UPDATE accounts SET balance = ...;
     UPDATE accounts SET balance = ...;
   COMMIT;
   ```

4. ✅ **及时释放连接**
   ```javascript
   finally {
     connection.release();  // 必须执行
   }
   ```
