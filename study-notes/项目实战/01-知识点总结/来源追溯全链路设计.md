# 来源追溯全链路设计

> 学习日期: 2026-05-04 | 置信度: ⭐⭐⭐

---

## 核心概念

SourceBadge 来源追溯的核心思路：**在切片阶段就打上元数据标签**，让每一条向量数据都携带"来自哪个文件、哪个标题"的信息，然后在搜索和对话阶段将这些信息传递到前端展示。

整个元数据管道分为四个环节：

1. **切片阶段（chunker）**: `chunkTextWithMetadata()` 在切片时生成 `ChunkMetadata`（fileName, title），与文本一起返回
2. **存储阶段（vector store）**: `addVectors` 接收可选的 `metas` 参数，FileStore 将 metas 数组持久化到 `vectors.json`
3. **检索阶段（chat API）**: 搜索结果中的 `SearchResult.meta` 被提取为 `SourceRef[]`，通过 AI SDK v6 的 `messageMetadata` 附加到流式响应
4. **展示阶段（UI）**: ChatPanel 泛型化 `useChat<MessageWithSources>`，渲染来源标签

## 关键类型定义

```typescript
// 切片元数据（chunker 阶段）
interface ChunkMetadata {
  fileName: string;  // 来源文件名
  title: string;     // 所属标题（markdown 标题分段）
}

// 搜索结果（vector store 返回）
interface SearchResult {
  id: string;
  score: number;
  text: string;
  meta: ChunkMetadata | null;  // 向后兼容旧数据
}

// 来源引用（传递到前端）
interface SourceRef {
  fileName: string;
  title: string;
  score: number;
}
```

## 全链路代码流

```typescript
// 1. chunker 阶段 — 生成带元数据的切片
const chunks = chunkTextWithMetadata(text, fileName, {
  chunkSize: 1000,
  overlap: 100,
});
// 返回: { text: string; meta: ChunkMetadata }[]

// 2. 存储阶段 — 向量 + 元数据一起写入
await vectorStore.addVectors(
  collectionName,
  embeddings,
  ids,
  chunks.map(c => c.meta)  // metas 参数
);

// 3. 检索阶段 — 提取来源信息
const results = await vectorStore.search(collectionName, queryEmbedding, topK);
const sources: SourceRef[] = results
  .filter(r => r.meta !== null)
  .map(r => ({
    fileName: r.meta!.fileName,
    title: r.meta!.title,
    score: r.score,
  }));

// 4. 通过 AI SDK v6 messageMetadata 附加到流
return new StreamingTextResponse(stream, {
  headers: { 'x-message-metadata': JSON.stringify({ sources }) },
});
```

## 向后兼容策略

旧版本的 `vectors.json` 没有 `metas` 字段。FileStore 读取时做了兼容处理：

```typescript
// FileStore.search() 中
const meta = collection.metas
  ? collection.metas[i] ?? null   // 新数据有 metas，但某条可能为空
  : null;                          // 旧数据没有 metas 字段，返回 null
```

这样旧数据升级后不会报错，只是搜索结果不带来源标签。

## 关键要点

1. **元数据在切片阶段就绑定**，而不是事后关联——避免了"谁是谁的"追溯难题
2. **向后兼容是必须考虑的**，不能因为新增字段就让旧数据全部失效
3. **AI SDK v6 的 messageMetadata** 是将附加信息传递到前端的正确方式，不是在流式文本里拼接 JSON
4. **前端 useChat 泛型化** 使得 TypeScript 可以类型安全地访问 metadata 中的 sources

## ❌ 常见错误与纠正（复习重点）⚠️

### 错误1：ChromaDB metadatas 不接受 null
- **错误示例**: `metas.map(m => m ?? null)` 传入 ChromaDB
- **错误原因**: ChromaDB 的 metadata 字段不接受 null 值，会抛出异常
- **正确理解**: 过滤掉 null，用空对象代替：`metas.map(m => m ?? {})`

### 错误2：旧数据没有 metas 字段导致崩溃
- **错误示例**: 直接 `collection.metas[i]` 访问
- **错误原因**: 旧版 vectors.json 没有 metas 字段，`collection.metas` 为 undefined
- **正确理解**: 先检查 metas 是否存在：`collection.metas ? collection.metas[i] ?? null : null`

### 错误3：多次上传产生孤儿向量
- **错误示例**: 同一文件上传多次，每次生成新的向量 ID
- **错误原因**: 优化前没有 chunkIds 机制，无法追溯哪些向量属于哪个文件
- **正确理解**: 需要在上传时记录 chunkIds，删除时按 chunkIds 清理对应向量
