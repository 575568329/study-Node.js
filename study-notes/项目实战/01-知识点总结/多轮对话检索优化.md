# 多轮对话检索优化

> 学习日期: 2026-05-04 | 置信度: ⭐⭐⭐

---

## 核心概念

多轮对话场景下，用户的后续问题往往缺少独立语义。比如用户先问"这个项目怎么安装？"，然后追问"还有别的安装方式吗？"。第二个问题如果单独做 embedding，向量搜索无法理解"别的安装方式"指的是什么。

**解决思路**：在构建搜索 query 时，把最近的对话上下文拼接进来，让 embedding 输入包含足够的语义信息。

## 代码示例

```typescript
/**
 * 构建多轮对话的搜索 query
 *
 * 策略：拼接最近 N 轮对话 + 当前问题
 * 仅影响 embedding 输入，LLM 仍接收完整原始消息
 */
function buildSearchQuery(
  messages: Array<{ role: string; content: string }>,
  currentQuestion: string,
  contextRounds: number = 2,  // 最近 2 轮
  maxChars: number = 500       // 截断到 500 字符
): string {
  // 从消息列表末尾往前取最近 contextRounds 轮
  const recentMessages = messages.slice(-contextRounds * 2);

  // 拼接上下文
  const context = recentMessages
    .map(m => `${m.role === 'user' ? '用户' : '助手'}: ${m.content}`)
    .join('\n');

  // 拼接当前问题
  const fullQuery = `${context}\n用户: ${currentQuestion}`;

  // 截断避免稀释关键信息
  return fullQuery.slice(-maxChars);
}

// 使用示例（chat route 中）
const searchQuery = buildSearchQuery(messages, currentQuestion);
const queryEmbedding = await getEmbedding(searchQuery);
const results = await hybridSearch(vectorStore, collectionName, queryEmbedding, currentQuestion, TOP_K);
```

## 设计要点

### 为什么只影响 embedding 输入

```
用户消息 → buildSearchQuery() → embedding → 向量搜索 → 检索结果
                                          ↓
用户消息（原始）→ LLM → 回答（带检索结果作为 context）
```

- **embedding 用拼接后的 query**：包含上下文，语义更完整，搜索更准确
- **LLM 用原始消息**：完整的对话历史，不会因为截断丢失信息

### 为什么截断到 500 字符

embedding 模型有 token 上限，且过长的输入会**稀释**关键信息的权重。截断策略：
- 从末尾截取（保留最新的、最相关的信息）
- 500 字符约 150~250 个中文 token，在 embedding 模型的舒适区间内

### contextRounds 为什么是 2

- 取太多轮：噪声增加，可能引入不相关的话题
- 取太少轮：上下文不够，无法理解指代
- 2 轮（1 个来回）是经验上的平衡点

## 关键要点

1. **检索 query 和 LLM 输入可以不同**——这是 RAG 架构的重要灵活性
2. **截断从末尾取**：最新消息通常最相关
3. **拼接方式要明确角色**："用户: xxx\n助手: xxx" 让 embedding 理解对话结构
4. **参数可调**：contextRounds 和 maxChars 可根据实际效果调整

## ❌ 常见错误与纠正（复习重点）⚠️

### 错误1：把拼接后的 query 也给 LLM
- **错误示例**: `const prompt = buildSearchQuery(messages, question); await llm.chat(prompt);`
- **错误原因**: 拼接后截断的 query 丢失了完整对话信息，LLM 无法给出准确回答
- **正确理解**: embedding 用拼接 query，LLM 用原始 messages，两条路径独立

### 错误2：不截断，把整个对话历史都拼进去
- **错误示例**: `const fullQuery = allMessages.map(m => m.content).join('');`
- **错误原因**: 过长的输入会稀释 embedding 中的关键信息，搜索效果反而变差
- **正确理解**: 只取最近几轮，且截断到合理长度（500 字符）

### 错误3：contextRounds 取太多
- **错误示例**: `contextRounds = 10`，把 20 条历史消息都拼进来
- **错误原因**: 对话可能已切换话题，旧消息引入噪声
- **正确理解**: 2 轮通常是合适的平衡点，根据实际对话模式调整
