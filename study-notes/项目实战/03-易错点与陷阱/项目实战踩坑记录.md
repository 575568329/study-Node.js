## Day 3 踩坑（2026-05-03）

### 1. e.stopPropagation() 加错位置
- **现象**: 点击上传按钮触发卡片跳转到对话页
- **原因**: `<input type="file" hidden>` 是隐藏的，用户实际点击的是 `<label>`，stopPropagation 加在 input 上无效
- **修复**: 把 `onClick={(e) => e.stopPropagation()}` 加在 `<label>` 上

### 2. 集合名不匹配
- **现象**: 上传文档后对话搜不到相关内容
- **原因**: 上传接口用 `kb-${id}`，对话接口直接用 `kbId`
- **修复**: 统一为 `kb-${kbId}`，定义常量

### 3. JSON 文件持久化重启丢失
- **现象**: 刷新页面后知识库和文档记录消失
- **原因**: db.ts 使用内存变量，重启即清空
- **修复**: 改为读写 `data/db.json` 文件

### 4. 向量数据重复上传
- **现象**: 同一文件上传 3 次，36 条向量里大量重复
- **原因**: 无去重检查
- **修复**: 上传前检查 `db.listDocs()` 中是否已存在同名文件

### 5. embedding-3 对中文短片段相似度偏低
- **现象**: 用户问"怎么安装"，topScore 只有 0.5-0.6，真正的安装步骤排不进 top 3
- **原因**: embedding-3 模型对中文短片段语义理解有限
- **缓解**: TOP_K 调到 5，阈值降到 0.45
- **后续**: 需要混合搜索（向量 + 关键词 BM25）

## Day 4 踩坑（2026-05-04）

### 1. 单引号 vs 反引号 — 模板字符串变量不替换
- **现象**: XHR 请求路径是字面量 `/api/kb/${id}/upload`，变量没有被替换
- **原因**: 模板字符串用了单引号 `'/api/kb/${id}/upload'`，单引号是普通字符串，不会解析 `${}`
- **修复**: 改为反引号 `` `/api/kb/${id}/upload` ``

### 2. setState 异步读取旧值
- **现象**: `setLoadCode` 后立即 `console.log(loadCode)` 输出的是旧值
- **原因**: React 的 setState 是异步的，状态更新在下次渲染时才生效
- **修复**: 如需基于新值做操作，使用 `useEffect` 监听状态变化，或使用 setState 的函数形式

### 3. Toast 空消息仍渲染
- **现象**: Toast 组件在 message 为空字符串时仍然渲染（显示空白的提示框）
- **原因**: 条件判断只检查了 Toast 的 message 字段，没有检查整个 toast 对象
- **修复**: 改为 `toast` 为 `null` 时不渲染组件：`{toast && <Toast ... />}`

### 4. JSX 三元表达式括号嵌套错误
- **现象**: 编译报错，提示多了一个 `</div>`
- **原因**: 三元表达式嵌套时括号没有正确匹配，多写了一个闭合标签
- **修复**: 仔细检查三元表达式的括号层级，确保每个分支的 JSX 标签正确闭合

## Day 5 踩坑（2026-05-04 — 项目优化）

### 1. ChromaDB metadatas 不接受 null
- **现象**: 向 ChromaDB 写入带 metadata 的向量时报错
- **原因**: ChromaDB 的 metadata 字段不接受 null 值，传入 null 会抛出异常
- **修复**: 过滤掉 null 值，用空对象代替：`metas.map(m => m ?? {})`

### 2. 旧 vectors.json 没有 metas 字段 — 向后兼容崩溃
- **现象**: 旧版数据没有 metas 字段，访问 `collection.metas[i]` 时 collection.metas 为 undefined
- **原因**: FileStore 持久化新增了 metas 字段，但旧数据文件中没有这个字段
- **修复**: 先检查 metas 是否存在：`collection.metas ? collection.metas[i] ?? null : null`

### 3. 多次上传产生孤儿向量数据
- **现象**: 同一文档上传多次后，删除文档只删了一份向量，其余变成"孤儿数据"
- **原因**: 优化前没有 chunkIds 机制，多份向量无法追溯到同一个文档
- **修复**: 后续需要在上传时记录 chunkIds，删除时按 chunkIds 批量清理

### 4. 混合搜索 RRF 分数被阈值过滤
- **现象**: 混合搜索返回空结果
- **原因**: RRF 融合分数约 0.016，但代码沿用了余弦相似度的 0.45 阈值过滤
- **修复**: 混合搜索不做固定阈值过滤，直接按 RRF 分数排序取 topK

### 5. TypeScript 类型推断 — collection.metas 可能为 undefined
- **现象**: TypeScript 编译报错，提示可能为 undefined
- **原因**: `collection.metas` 类型是 `ChunkMetadata[] | undefined`，直接索引访问不安全
- **修复**: 赋值给临时变量并做 nullish 检查，或使用可选链 `collection.metas?.[i] ?? null`

## Day 6 踩坑（2026-05-05 — 前端 UI 优化）

### 1. react-force-graph-2d 没有 cameraPosition 方法
- **现象**: 调用 `graphRef.current.cameraPosition()` 报 TypeError: cameraPosition is not a function
- **原因**: `cameraPosition` 是 3D 版本（react-force-graph-3d）的 API，2D 版本使用完全不同的 API
- **修复**: 2D 版本使用 `centerAt(x, y, ms)` 平移视角 + `zoom(level, ms)` 缩放，3D 版本才用 `cameraPosition({ x, y, z })`
- **教训**: 2D 和 3D 的 API 不能混用，查文档时要确认版本

### 2. Tailwind hidden 类被 CSS 规则覆盖
- **现象**: file input 设置了 Tailwind `hidden` 类，但仍然可见，显示"选择文件, 未选择文件"
- **原因**: Tailwind 的 `hidden` 类（`display: none`）优先级较低，可能被其他 CSS 规则覆盖
- **修复**: 改用 inline style `style={{ display: 'none' }}`，inline style 优先级最高，不会被覆盖
- **教训**: 当 Tailwind 工具类"不生效"时，优先考虑 CSS 优先级问题

### 3. flex 布局 h-full 高度传递断裂
- **现象**: 图谱页面画布不可见，检查发现高度为 0
- **原因**: Next.js 页面从 layout → page → component 的 `h-full` 链需要在**每一层**都是 flex 容器。中间任何一层缺少 `flex` 或 `h-full`，高度就无法传递下去
- **修复**: 确保每一层都设置 `flex flex-col h-full`：
  - `layout.tsx`: `<body className="flex flex-col h-full">`
  - `page.tsx`: `<main className="flex flex-col h-full">`
  - 组件: `<div className="flex flex-col flex-1">`
- **教训**: flex 布局的 h-full 是一条链，任何一环断裂都会导致子元素高度塌缩

### 4. 图谱无数据根因 — 上传流程未调用实体提取器
- **现象**: 图谱页面完全空白，没有任何节点和边
- **原因**: 上传文档的完整流程是"切片 → 向量化 → 存储"，但从未调用 `entity-extractor.ts`（AI 实体提取器），所以 `graph.json` 从未被创建
- **修复**: 在上传流程中增加实体提取步骤：上传 → 切片 → 向量化 → **实体提取（glm-4-flash + structured output）** → 写入 GraphStore
- **教训**: 数据流中的每个环节都需要确认是否被调用，不能假设"应该会被调用"
