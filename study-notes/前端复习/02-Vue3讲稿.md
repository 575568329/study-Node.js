## Q1：ref vs reactive + 为什么 .value ✅

**区别**：
- **ref**：存基本类型（也兼容对象），用时要 `.value`
- **reactive**：存对象，直接用属性名，不用 `.value`

**为什么 ref 要 .value**：
- ref 底层是 **RefImpl 类的实例**（new 的是类实例，不是函数）
- JS 没法拦截"读裸变量"，只能拦"读对象属性"
- 所以强行包一层对象，用 `.value` 这个固定属性名去触发 **get/set**
- `.value` 就是触发 get/set 的钥匙

```javascript
class RefImpl {
  constructor(value) { this._value = value; }
  get value() { track(); return this._value; }   // 读 → 依赖收集
  set value(v) { this._value = v; trigger(); }    // 写 → 触发更新
}
const count = new RefImpl(0);
count.value++;  // 触发 get + set
```

**为什么 reactive 不用 .value**：
- reactive 用 **Proxy** 拦截整个对象的每个属性
- 对象天然有多个属性，直接用属性名（user.age），Proxy 就能拦到，不需要额外的 .value

| | ref | reactive |
|---|---|---|
| 底层 | RefImpl 类 + get/set | Proxy 代理整个对象 |
| 拦截 | `.value` 一个属性 | 对象每个属性 |
| 为什么 | 基本类型没法拦,包对象 | 对象天然多属性,Proxy 全拦 |

**面试一句话**：ref 用 .value 是因为基本类型没法拦，只能包成对象用 .value 触发 get/set；reactive 用 Proxy 直接拦每个属性，所以用属性名，不需要 .value。

## Q2：Vue3 为什么用 Proxy 替代 defineProperty ✅

**根因：拦截粒度不同。**
- defineProperty：**属性级**粒度（per-property），逐个属性装"传感器"，漏装就拦不到
- Proxy：**对象级**粒度（per-object），整个对象套代理，任何操作都过"大门"被拦

**Vue2 (defineProperty) 三大缺陷**：
1. **新增属性不响应**：`vm.user.age = 29` 不更新（要 `Vue.set`）
2. **删除属性不响应**：`delete vm.user.name` 不更新
3. **数组下标/length 不响应**：`vm.list[0] = x` 不更新（Vue2 hack 7 个数组方法）

根因：defineProperty 只能拦"初始化时存在的属性"，涉及不存在的属性就拦不到。

**Vue3 (Proxy) 全解决**：
- Proxy 拦截整个对象，新增/删除/数组下标**天然响应**
- 删除属性走 `deleteProperty` 拦截器，也能监听
- 能拦截 **13 种操作**（get/set/has/deleteProperty/ownKeys...）

| | defineProperty (Vue2) | Proxy (Vue3) |
|---|---|---|
| 粒度 | 属性级 | 对象级 |
| 新增属性 | ❌ 要 Vue.set | ✅ 天然响应 |
| 删除属性 | ❌ | ✅ deleteProperty |
| 数组下标 | ❌ hack 7 方法 | ✅ 天然响应 |
| 拦截操作 | 只有 get/set | 13 种 |

**面试一句话**：Vue2 用 defineProperty 是属性级粒度，只能拦初始化时存在的属性，新增/删除/数组下标都不响应；Vue3 用 Proxy 是对象级粒度，整个对象的操作都拦截，全部天然响应。

## Q3：依赖收集（track/trigger）✅

**核心机制**：Vue 怎么知道"数据变了要更新哪块 DOM"？→ **提前记录谁用了我，变了再通知**。

**effect 是什么**：会用到响应式数据的"东西"（页面渲染、computed、watch），Vue 统一叫 effect。
- **effect 是 Vue3 自己加的，原生 JS 没有**
- 业务代码几乎不直接写 effect，Vue 背后帮你把渲染/computed/watch 包装成 effect
- effect 执行时读了响应式数据 → 触发 get → track 记录

**track（get 时执行）**：记录"当前 effect 依赖了我这个数据"
```javascript
get value() {
  track(this);           // 把 activeEffect 存进依赖集合
  return this._value;
}
```

**trigger（set 时执行）**：通知"所有依赖我的 effect 重新执行"
```javascript
set value(newVal) {
  this._value = newVal;
  trigger(this);         // 取出存的 effect,逐个重新执行 → 页面更新
}
```

**三层依赖结构（记死）**：
```
WeakMap (仓库)        ← 对象 → depsMap,弱引用防内存泄漏
  └─ depsMap (Map)    ← 属性名 → Set,区分是哪个属性的依赖
       └─ Set<effect> ← 一个属性被多个 effect 依赖(一对多)
```

每层解决一个问题：
1. WeakMap：区分"哪个对象"（弱引用,对象销毁自动回收,防泄漏）
2. depsMap(Map)：区分"哪个属性"（精确更新,改 name 不通知 age 的依赖）
3. Set：一个属性被多个 effect 依赖（一对多）

**为什么用 WeakMap 不用 Map**：弱引用，对象销毁时依赖记录自动被垃圾回收，防内存泄漏。

**面试一句话**：track 在 get 时记录"当前 effect 依赖了我"，trigger 在 set 时通知"所有依赖我的 effect 重新执行"。用 WeakMap→Map→Set 三层结构，精确到属性级更新，所以不是整个页面重渲染。

### 关键补充：ref vs reactive 的依赖存储位置（重要区别！）

**依赖存哪不一样**：
- **ref**：依赖存在**实例自己的 `dep` 属性**上（`num.dep = Set<effect>`）
- **reactive**：依赖存在**外部全局 targetMap（WeakMap）**里，**不碰原对象**

```
【ref】依赖在实例自己身上
num (RefImpl 实例)
├── _value = 0          ← 值
└── dep = Set<effect>   ← 依赖(自己挂的属性)

【reactive】依赖在外部全局仓库,obj 保持干净
targetMap (WeakMap)
└─ key: obj → depsMap (Map)
                ├─ 'name' → Set<effect>
                └─ 'age'  → Set<effect>
```

**为什么 reactive 不把依赖存在 obj 里**：
1. 不能污染用户的对象（obj 是用户传进来的，Vue 不能往里塞东西）
2. ref 能挂自己的属性，是因为 RefImpl 实例是 Vue 造的，可以随便挂

**为什么 reactive 必须用 WeakMap，ref 不用**：
- reactive 要区分"哪个对象的依赖"（多个对象），key 是对象，弱引用防泄漏
- ref 实例自己就是独立单位，依赖挂自己身上即可

**reactive 的查找路径（track 干的事）**：
```javascript
targetMap.get(obj).get('属性名').add(effect)
//  obj → depsMap → 'name' → Set → 把 effect 存进去
```

**⚠️ 易混点**：
- reactive 的 depsMap key 是**对象属性名**（'name'、'age'）
- ref 不走 depsMap，直接 dep = Set（因为只有 .value 一个属性，不用区分）

**dep 能直接访问吗**：不能，是 Vue 内部属性，业务代码访问不到。看依赖用 Vue Devtools。

### 版本说明 & 参考来源（避免看源码困惑）

**⚠️ 版本差异**：Vue 3.4 重构了响应式系统，引入了 `Dep` 类（不再用裸 `Set`）。
- 本讲稿用 `Set<effect>` 是**概念简化**，理解依赖收集完全够用
- 看源码时：3.4+ 的 `dep` 是 `Dep` 实例（内部还是装 effect），概念一致
- 面试讲概念用 Set/Dep 都行，核心是"装 effect 的集合"

**已查证正确（2026-07-17 对比权威资料）**：
- 三层结构 `targetMap(WeakMap) → depsMap(Map) → dep(Set)`：✅ 正确
  来源：Vue 官方文档、edison1105 深度文章、dev.to 实现解析
- track 在 get / trigger 在 set：✅ 正确
- WeakMap 防内存泄漏：✅ 正确
- ref 依赖挂实例自身、reactive 在全局 targetMap：✅ 正确
