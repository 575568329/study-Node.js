## 一、Vue3 vs Vue2 核心变化

### 1.1 Options API → Composition API

Vue2 的 **Options API** 将数据分散在 `data`、`methods`、`computed`、`watch` 中，查看变量和函数关系需要频繁上下滚动。

Vue3 的 **Composition API** 将数据和方法集中在 `<script setup>` 中，变量可以直接在函数中定义，函数可以单独抽成文件封装，暴露数据和方法供页面使用，不影响双向绑定。

```typescript
// Options API (Vue2) — 按类型分散
export default {
  data() { return { count: 0 } },
  methods: { increment() { this.count++ } },
  computed: { double() { return this.count * 2 } }
}

// Composition API (Vue3) — 按功能聚合
<script setup lang="ts">
const count = ref(0)
const increment = () => count.value++
const double = computed(() => count.value * 2)
</script>
```

**React 的 JSX** 进一步将方法、数据、HTML 都放在一个函数中，和 Vue3 使用方式类似。

### 1.2 Vue3 vs React 思维差异

| | Vue3 | React |
|---|---|---|
| 文件结构 | `<script setup>` + `<template>` 分离 | 一个函数包含全部 |
| 语法 | 模板语法（`v-if`, `v-for`, `@click`） | JSX（就是 JS） |
| 响应式 | 数据变化自动监听 | 需要手动调用 setter |
| 更新机制 | 精确追踪变化 | setter 触发 → 函数整体重新执行 |

## 二、响应式数据

### 2.1 ref（基本类型首选）

```typescript
const count = ref(0)
count.value++        // 脚本中用 .value
// 模板中直接用 {{ count }}，自动解包
```

### 2.2 reactive（对象类型）

```typescript
const user = reactive({ name: 'Alice', age: 30 })
user.name = 'Bob'   // 不需要 .value，直接访问属性
```

**重要限制：reactive 不能整体重新赋值，会丢失响应性**

```typescript
// ❌ 响应性断了
user = { name: 'Bob', age: 25 }

// ✅ 用 ref 包装对象，整体赋值
const user = ref({ name: 'Alice', age: 30 })
user.value = { name: 'Bob', age: 25 }  // 触发双向绑定
```

**选择规则：**
- 基本类型 → `ref`
- 对象且不会整体替换 → `reactive`
- 对象但可能整体替换（如接口返回数据） → `ref`

### 2.3 React 的状态管理

React 数据变化不会自动更新 DOM，需要手动调用 setter：

```tsx
const [count, setCount] = useState(0)
setCount(2)  // 更新数据 + 触发 DOM 更新

// 状态不可变：必须创建新值，不能直接修改
const [todos, setTodos] = useState<string[]>([])
setTodos([...todos, newItem])  // ✅ 展开创建新数组
todos.push(newItem)            // ❌ 不会触发渲染
```

## 三、computed 与 watch

### 3.1 computed（派生状态）

自动追踪依赖，依赖数据变化时自动重新计算：

```typescript
const doubleCount = computed(() => count.value * 2)
```

### 3.2 watch（监听变化，执行副作用）

```typescript
// 监听 ref
watch(count, (newVal, oldVal) => {
  console.log(`变化: ${oldVal} → ${newVal}`)
})

// 监听 reactive 属性 — 需要用 getter 函数（一层箭头函数）
watch(() => todo.items.length, (newLen) => {
  console.log(`数量变化: ${newLen}`)
})
```

**使用场景：**
- `computed`：根据现有数据**算出新数据**
- `watch`：数据变化时**执行操作**（异步请求、DOM 操作、日志）

### 3.3 React 的 useEffect（watch + onMounted 合体）

```tsx
// = watch — count 变化时执行
useEffect(() => {
  console.log('count 变了:', count)
}, [count])

// = onMounted — 空依赖数组，只执行一次
useEffect(() => {
  console.log('组件挂载')
  return () => console.log('组件卸载')  // return = onUnmounted
}, [])
```

**关键区别：useEffect 在渲染之后执行（不是渲染前）**

```
React 执行顺序：函数体 → DOM 更新 → useEffect
Vue3 执行顺序：状态变化 → watch 回调 → DOM 更新
```

## 四、生命周期

### 4.1 Vue2 → Vue3 映射

| Vue2 | Vue3 Composition API |
|------|---------------------|
| `beforeCreate` / `created` | `<script setup>` 顶层代码替代 |
| `beforeMount` | `onBeforeMount` |
| `mounted` | `onMounted` |
| `beforeUpdate` | `onBeforeUpdate` |
| `updated` | `onUpdated` |
| `beforeDestroy` | `onBeforeUnmount` |
| `destroyed` | `onUnmounted` |

### 4.2 执行顺序

`<script setup>` 顶层代码在组件创建时立即执行，**比 onMounted 更早**：

```
1. <script setup> 顶层代码  ← setup() 阶段
2. onBeforeMount
3. onMounted                ← 此时 DOM 才可用
```

## 五、Props、Emits 与 TypeScript

### 5.1 defineProps（泛型声明）

```typescript
// TS 泛型声明 — 编译时类型检查
defineProps<{
  title: string
  count?: number  // 可选
}>()

// 带默认值
withDefaults(defineProps<{
  title: string
  count?: number
}>(), {
  count: 0
})
```

与运行时声明的区别：泛型声明用 `string`（TS 类型），运行时用 `String`（JS 构造函数）。泛型声明提供完整的 IDE 智能提示和编译时类型检查。

### 5.2 defineEmits（类型安全的事件定义）

```typescript
defineEmits<{
  remove: [index: number]
  update: [id: string, value: string]
}>()
// emit('remove', 'abc')  ← 编译报错，类型不匹配
```

### 5.3 defineExpose（暴露子组件方法）

Vue3 子组件默认封闭，必须显式暴露才能被父组件 ref 访问：

```typescript
// 子组件
const highlight = () => { console.log('高亮') }
defineExpose({ highlight })
```

### 5.4 React 对比

React 没有单独的 emit 概念，**事件就是普通函数 props**：

```tsx
interface Props {
  text: string
  onRemove: (index: number) => void  // 事件 = 函数 props
}
function TodoItem({ text, onRemove }: Props) { ... }
```

## 六、模板引用 ref

### 6.1 Vue3

```typescript
// 声明（变量名必须和模板中 ref="xxx" 一致）
const inputRef = ref<HTMLInputElement | null>(null)
// 脚本中使用
inputRef.value?.focus()

// 获取子组件实例类型
const childRef = ref<InstanceType<typeof ChildComponent> | null>(null)
```

`ref<HTMLInputElement | null>(null)` 拆解：
- `<HTMLInputElement | null>` — 泛型类型参数，告诉 TS 未来持有哪种值
- `(null)` — 函数调用的实参（初始值）

### 6.2 React

```tsx
const inputRef = useRef<HTMLInputElement>(null)  // .current 而非 .value
inputRef.current?.focus()
// JSX: <input ref={inputRef} />  注意是花括号，不是字符串
```

**useRef vs useState**：useRef 改 `.current` 不触发渲染，适合存不影响界面的数据（定时器 ID 等）。

## 七、Composables（组合式函数）

封装可复用的响应式逻辑，替代 Mixin：

```typescript
// composables/useCounter.ts
export function useCounter(initial = 0) {
  const count = ref(initial)
  const increment = () => count.value++
  return { count, increment }
}

// 组件中使用 — 来源明确
const { count, increment } = useCounter()
```

**Mixin 的问题 → Composable 的解决**：
- 来源不明 → 显式解构，变量从哪来一目了然
- 命名冲突静默覆盖 → 可重命名 `const { count: c } = useCounter()`
- TS 类型推导差 → 完美类型推导

## 八、Pinia 状态管理

### 8.1 核心变化

Pinia 替代 Vuex。核心简化：**去掉 mutations，actions 直接改 state**。

```
Vuex:  state → mutations (同步) → actions (异步)   三层
Pinia: state → actions (同步异步都行)                一层
```

### 8.2 Setup Store 语法

```typescript
export const useCounterStore = defineStore('counter', () => {
  // state
  const count = ref(0)
  // getters
  const doubleCount = computed(() => count.value * 2)
  // actions（同步异步都写这里）
  const increment = () => count.value++
  const fetchRandom = async () => {
    const res = await fetch(url)
    count.value = (await res.text()).length  // 直接改 state
  }
  return { count, doubleCount, increment, fetchRandom }
})
```

### 8.3 使用 store

```typescript
import { storeToRefs } from 'pinia'

const counterStore = useCounterStore()
// 数据（state/getters）必须用 storeToRefs 解构，否则丢失响应性
const { count, doubleCount } = storeToRefs(counterStore)
// 方法（actions）直接解构
const { increment, reset } = counterStore
```

## 九、Vue Router 4 + TypeScript

### 9.1 路由配置

```typescript
const routes = [
  {
    path: '/user/:id',
    name: 'user',
    component: () => import('../views/UserView.vue'),
    props: true  // 路由参数作为 props 传入组件
  }
] as const  // 让路由信息变成字面量类型
```

### 9.2 组件接收路由参数

```typescript
// 推荐方式：props: true + defineProps
defineProps<{ id: string }>()

// 备选方式：useRoute（组件会依赖 router，不利于测试）
const route = useRoute()
const id = route.params.id as string  // 类型为 string | string[]，需收窄
```

**props: true 更好**：组件不知道自己是从路由来的，测试时直接传 props 即可，不需要 mock router。

### 9.3 路由守卫

```typescript
router.beforeEach((to, from) => {
  console.log(`导航: ${from.path} → ${to.path}`)
  // return false 可取消导航
})
```

## 十、API 分层架构（实战总结）

```
types/index.ts    → 定义"数据长什么样"（interface）
api/request.ts    → 定义"怎么拿到数据"（Axios 封装 + 拦截器）
api/user.ts       → 定义"具体的业务 API"（类型安全的请求方法）
composables/      → 定义"怎么管理数据状态"（loading/error/数据）
组件              → 定义"怎么展示和交互"
```

**示例：类型安全的 API 封装**

```typescript
// types/index.ts
export interface User { id: number; name: string; email: string }

// api/request.ts — 泛型封装
export async function get<T>(url: string): Promise<T> {
  return request.get(url)
}

// api/user.ts — 业务 API
export const userApi = {
  getList: () => get<User[]>('/users'),
  create: (data: CreateUserRequest) => post<User>('/users', data)
}
```

const formErrors = computed(() => {
