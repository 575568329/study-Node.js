# RAG 项目体检清单

更新时间：2026-05-07

## 体检目标

确认 `rag-docs-assistant` 是否足以支撑“全栈 AI 应用项目”定位。

体检结果要输出四类结论：

1. 已完成能力。
2. 简历可写点。
3. 面试风险点。
4. 必须补齐项。

## 代码结构检查

- [ ] 项目启动命令是否清晰。
- [ ] README 是否完整。
- [ ] 路由结构是否清楚。
- [ ] API Route 是否按业务拆分。
- [ ] 类型定义是否集中。
- [ ] 服务层 / 工具函数是否有清晰边界。
- [ ] 是否存在无关 demo 或废弃代码。

## 功能链路检查

### 知识库

- [ ] 创建知识库。
- [ ] 删除知识库。
- [ ] 选择知识库。
- [ ] `kbId` 是否贯穿文档、对话、图谱。

### 文档上传与解析

- [ ] 支持 `.txt`。
- [ ] 支持 `.md`。
- [ ] 支持 `.pdf`。
- [ ] 支持 `.docx`。
- [ ] 支持 `.xlsx`。
- [ ] 文件大小校验。
- [ ] 同名文件处理。
- [ ] 上传进度展示。
- [ ] 解析失败状态。

### 切片与向量化

- [ ] chunkSize 和 overlap 有明确配置。
- [ ] 切片保留来源元数据。
- [ ] 批量 embedding。
- [ ] embedding 失败处理。
- [ ] FileStore / Chroma 抽象边界清楚。

### RAG 问答

- [ ] 查询向量化。
- [ ] 多轮上下文拼接。
- [ ] 向量检索。
- [ ] 关键词检索。
- [ ] 混合检索 / RRF。
- [ ] Top-K 选择。
- [ ] Prompt 注入上下文。
- [ ] SSE / AI SDK 流式回答。
- [ ] 来源引用返回。
- [ ] 无命中时明确提示。

### 知识图谱

- [ ] 文档节点。
- [ ] 实体节点。
- [ ] 关系边。
- [ ] 搜索。
- [ ] 收藏。
- [ ] 节点详情。
- [ ] 图谱生成失败处理。

## 后端能力检查

- [ ] API Route 入参校验。
- [ ] 统一错误处理。
- [ ] 日志记录。
- [ ] 文件上传异常处理。
- [ ] 任务状态管理。

## 面试追问准备

每个问题都要准备 1-2 分钟回答：

- [ ] 为什么要做文档切片？
- [ ] chunkSize 怎么定？
- [ ] overlap 有什么作用？
- [ ] 为什么要混合检索？
- [ ] RRF 怎么理解？
- [ ] 向量库和业务库怎么分工？
- [ ] 为什么当前用 JSON FileStore？
- [ ] 如果数据量变大怎么演进？
- [ ] SSE 和 WebSocket 区别？
- [ ] 上传失败如何恢复？
- [ ] 如何避免模型胡说？
- [ ] 来源引用如何对应原文？
- [ ] 图谱抽取为什么异步？
- [ ] 如何做权限和多用户？
- [ ] 如何部署？
