## 学习目标

### 终极目标
**能完成工作 + 能讲清楚为什么这么做**

### 具体标准
1. **读懂代码**：能理解公司 Java 代码的业务逻辑和技术实现
2. **修改代码**：能修改 bug、添加简单功能，知道改哪里、为什么这么改
3. **独立开发**：能写一个简单的 CRUD 接口，知道每一行代码的作用
4. **技术沟通**：能和后端同事对话，听懂他们说的技术术语
5. **原理理解**：不只是会用，还能解释 Spring 为什么这么设计、Dubbo 解决了什么问题

## 学习原则

### 1. 对比学习（利用你的 Node.js 基础）

每学一个 Java 概念，先问：
- Node.js 里怎么做的？
- Java 为什么要这么设计？
- 两者的本质区别是什么？

**示例**：
```markdown
## Spring 依赖注入

### Node.js 里怎么做？
const userService = require('./userService');
// 直接引入，手动管理依赖

### Java 为什么要这么设计？
@Autowired
private UserService userService;
// 由容器管理，解耦代码和依赖

### 本质区别
- Node.js：运行时动态加载，灵活但依赖关系隐式
- Java：编译时静态注入，强类型约束，依赖关系显式
```

---

### 2. 三遍学习法

#### 第一遍：跑通（知道怎么用）
- 照着教程敲代码
- 跑起来，看到效果
- 记录不理解的地方

#### 第二遍：理解（知道为什么）
- 研究每个注解/配置的作用
- 读官方文档
- 对比不同写法的区别

#### 第三遍：应用（能讲清楚）
- 在公司代码里找类似场景
- 用自己的话向别人解释
- 写笔记总结原理

---

### 3. 边学边问（主动理解）

遇到新概念时，必问五个问题：
1. **是什么**？（定义）
2. **解决什么问题**？（背景）
3. **怎么用**？（API）
4. **为什么这么设计**？（原理）
5. **和我已知的 XX 有什么区别**？（对比）

---

### 4. 实战驱动（不做玩具项目）

所有练习都围绕两个目标：
1. **读懂公司代码**：从公司实际代码中找案例
2. **补强简历项目**：写一个能讲 20 分钟的 Java 项目

不做：
- ❌ 学生管理系统
- ❌ 图书管理系统
- ❌ 博客系统

要做：
- ✅ 用 Java 重写你的 RAG 知识问答后端
- ✅ 理解公司众包系统的核心业务
- ✅ 每学一个概念，在公司代码里找 3 个实际用法
