# 协作解题方法论（通用版）

> 提炼自本项目完整协作弧线：**"教学方式合理吗 → 查认知科学 → 通用+码农方法论 → 常规化成 skill → 实证校准"**。
> 对照三个公认方法论校准：**循证实践 EBP**、**设计科学研究 DSR**、**学习工程 Learning Engineering**。
> 适用：任何"我现在的做法合理吗 / 怎么做得更好"的非平凡疑问——教学、流程、设计、决策、排障。
> 与 [[学习方法论-通用与码农专项]] 互补：那份是"学什么/怎么学"的**内容**方法论；这份是"怎么把一个疑问工程化成可靠做法"的**过程**方法论。

---

## 0. 一句话

> **把任何"这合理吗"的疑问，走一条证据驱动的工程化路径——质疑→查证→批判评估→本土化→工程化→实证校准；每步内嵌"求证小循环"，全程挂两道护栏（反迎合 / 现实拟合）。**

核心信念：**做法（practice）是可以当"制品（artifact）"来建和评的**——先问它有没有证据支撑，再把它落成可重复执行的机制，最后拿真实使用数据验。不是拍脑袋、不是找个源引用一下就算。

---

## 1. 为什么可信：我们独立重演了三个公认方法论

这次完整复盘后发现，我们的弧线**几乎逐段对应**三个有学术背书的方法论。这不是事后贴金——是流程本身经得起对照，所以可以放心当通用法：

| 我们实际做的 | 循证实践 EBP（5 步） | 设计科学研究 DSR | 学习工程 Learning Eng. |
|---|---|---|---|
| "本项目的教学方式合理吗？" | ① Ask（PICO 提问） | Problem identification | 始于 learner 的 challenge |
| 查 Cepeda/Roediger/FSRS/Ko… | ② Acquire（最强证据） | 文献调研 | 应用 learning science |
| 5 轮审计 + 证据分级 + 杀"学习金字塔 90%"神话 | ③ **Appraise（评证据效力）** | — | — |
| 通用层 + 码农专项层（两层架构） | ④ Apply（结合专长/情境） | Objectives + Design | 领域适配 |
| 写成 kp-verify / pre-session / update-progress | — | ⑤ Build artifact | **Operationalize → routine** |
| 派 agent 读 transcript 验触发，发现错配→改 | ⑤ Assess（评结果） | ⑥ Evaluation + 迭代 | iterate |

**结论**：流程不是我们编的，是 EBP + DSR + Learning Engineering 的自然交汇。下面把三者的精华**合并成一条管线**，并用它们补我们当时做得不够正式的地方。

---

## 2. 外层管线：6 步（证据驱动的实践工程化）

```
① 质疑 → ② 查证 → ③ 批判评估 → ④ 本土化 → ⑤ 工程化 → ⑥ 实证校准
                                                            ↓
                       发现问题 → 回到对应步骤迭代 ←─────────┘
```

| 步 | 做什么 | 这次怎么做的 | 对应 | 反面（坑） |
|---|---|---|---|---|
| **① 质疑** | 把模糊疑问变成**可查证问题** | "教学方式合理吗"→ 拆成"间隔/提取/迁移/读代码 各有没有证据" | EBP·Ask / DSR·Problem | 问得太泛，没法查证 |
| **② 查证** | 找**最强证据**，不靠记忆 | 查同行评审（Cepeda 1070 引、Roediger 5000 引）、官方源、benchmark | EBP·Acquire | 凭印象给数字/规范 |
| **③ 批判评估** | **给证据分级、杀神话、标局限** | 🟢🟠🔵⚪ 四级 + 删"教学留存 90%"+ 加"已知局限"7 条 | EBP·**Appraise** | 把所有来源写得一样权威 |
| **④ 本土化** | 区分**通用结论 vs 领域专项**，不盲目套 | 通用学习机制（地基）+ 码农 4 层额外处理（迁移/读代码/外部化） | EBP·Apply / DSR·Design | 拿通用研究直接套编程技能 |
| **⑤ 工程化** | 落成**可重复执行的机制**（skill/流程/工具） | 方法论 → kp-verify / pre-session / update-progress | DSR·Build / LE·Operationalize | 只写文档不机制化，下次又靠自觉 |
| **⑥ 实证校准** | 拿**真实使用数据**验，迭代 | 对比 transcript → 发现触发词错配 → 改事件驱动 | EBP·Assess / DSR·Evaluation | 交付即结束，不验真实拟合 |

> **关键**：⑤工程化和⑥实证校准是很多人会漏的两步。我们这次差点也漏（触发词没验就交付）。把它们**列为正式步骤**就是从 DSR/Learning Engineering 学来的最大优化。

---

## 3. 内层引擎：每一步都跑的"求证小循环"

外层 6 步是大节奏；**每一步内部**都用这个小循环保证严谨：

```
锚定 → 断言 → 求证 → 纠偏 → 沉淀（迭代）
```

| 步 | 动作 | 要点 |
|---|---|---|
| 锚定 | 对齐"这步要解决什么、验收标准" | 一句话说清，别急着做 |
| 断言 | 给出方案/事实/设计 | **每条标注** ✅已证实 / ⚠️推测 |
| 求证 | 对⚠️推测查权威 | 分两半：**规范正确性**（查文档）+ **现实拟合度**（查真实数据） |
| 纠偏 | 错了认→搜→改→记 | 不辩解、记录原误解 |
| 沉淀 | 落盘成可复用资产 | 文档/记忆/skill/错题本 |

> 求证两半最关键——**这次最大的弯路就栽在只做了一半**：触发的规范正确性验了（符合 skill spec），现实拟合度没验（没查真实对话），导致返工。设计型问题（多解）必须补现实拟合度。

---

## 4. 两道护栏（全程挂着）

### 🛡️ 护栏一：反迎合（Anti-Sycophancy）
**敌人**：sycophantic AI——agent 顺着用户说、夸对，导致判断退化、认知外包（Gerlich 2025 引 1600+；FABBS 2026）。我们这次的方法论**整层都是反这个的**：自我评估不可靠（Kruger-Dunning 1999），掌握度必须靠客观判据 + 外部反馈，不接受"我觉得会了"。
**执行**：评价客观不迎合；结论要有客观证据、不接受 agent 自评；对抗验证用独立角色 agent。

### 🛡️ 护栏二：现实拟合（Reality-Fit Gate）
**敌人**：凭假设设计、只看规范不看实际。
**执行**：任何依赖用户行为/触发/交互的结论，**发货前必须**拿真实数据（历史记录/对话样本）验一遍；区分**活动拟合**（动作接不接受）vs **触发拟合**（时机对不对）——两者可能错配；拿不准先小范围试。

## 5. 三个标志性技术（让本方法论 ≠ "找个源引用一下"）

这三个是我们这次做得**比朴素"查个资料"更强**的地方，也是可直接复用的：

1. **证据分级 + 诚实声明**（来自第③步）——给每条结论标 🟢实证/🟠外推/🔵启发式/⚪框架，并单列"已知局限"。校正证据诚实度 = 校正后续决策。学习金字塔"90%留存"神话就是靠这个杀掉的。
2. **通用 / 专项分层**（来自第④步）——不盲目套通用研究。先把"对所有学习都成立的机制"和"本领域额外的处理"分开，再决定优先级（码农：迁移+读代码优先于通用记忆机制）。
3. **build-evaluate 迭代**（来自第⑤⑥步，DSR 精华）——制品（skill/流程）建好就验，验了就改，是**规定的循环**不是可选。命名它，就不怕"做成 skill 是不是过度工程"——Learning Engineering 明确说：把学习科学 operationalize 成 routine 就是一门正经学科。

---

## 6. 适用边界

- ✅ **用**：质疑某做法合理性、想把直觉变成可靠机制、设计/决策/排障类问题。
- ❌ **不用**：单事实查询（直接搜）、闲聊、明确指令的纯执行（直接做）。
- ⚠️ **按问题类型调重心**：
  - **验证型**（有对错，如 API/公式）→ 重 ②③（查证+评估）。
  - **设计型**（多解，如触发/交互）→ 重 ⑤⑥（工程化+实证校准），**现实拟合护栏必须启用**。
  - **方法质疑型**（如"教学方式合理吗"）→ 走满 6 步，③证据分级是命门。
