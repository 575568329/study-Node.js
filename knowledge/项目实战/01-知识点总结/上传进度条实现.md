## 核心概念

### 为什么不能用 fetch 监听上传进度？

fetch API 的设计目标是简洁和标准化，但它**没有提供上传进度监听接口**。这是 fetch 的已知限制。

- `fetch` 返回的 `Response.body`（ReadableStream）只能监听**下载**进度
- **上传进度**需要使用 `XMLHttpRequest`（XHR）

### XMLHttpRequest upload.onprogress

XHR 提供了 `upload` 属性，上面有 `onprogress` 事件，可以实时获取上传进度：

```typescript
const xhr = new XMLHttpRequest();
xhr.open('POST', '/api/kb/kb-001/upload');

xhr.upload.onprogress = (event) => {
  if (event.lengthComputable) {
    // event.loaded: 已上传字节数
    // event.total: 总字节数
    const percent = Math.round((event.loaded / event.total) * 100);
    console.log(`上传进度: ${percent}%`);
  }
};

xhr.onload = () => {
  if (xhr.status === 200) {
    console.log('上传成功');
  }
};

xhr.onerror = () => {
  console.error('上传失败');
};

xhr.send(formData);
```

### Record 独立追踪多个知识库进度

当页面上有多个知识库时，需要独立追踪每个知识库的上传进度：

```typescript
// 使用 Record<知识库ID, 百分比> 追踪每个知识库的独立进度
const [uploadProgress, setUploadProgress] = useState<Record<string, number>>({});

// 上传时更新特定知识库的进度
xhr.upload.onprogress = (event) => {
  if (event.lengthComputable) {
    const percent = Math.round((event.loaded / event.total) * 100);
    setUploadProgress(prev => ({
      ...prev,
      [kbId]: percent  // 只更新当前知识库的进度
    }));
  }
};

// 渲染时读取
{uploadProgress[kbId] && (
  <div className="progress-bar">
    <div style={{ width: `${uploadProgress[kbId]}%` }} />
  </div>
)}
```

## 关键要点

1. **fetch vs XHR**: fetch 不支持上传进度，必须用 XHR 的 `upload.onprogress`
2. **模板字符串**: 动态 URL 必须用**反引号**（`` ` ``），单引号不会替换 `${}` 变量
3. **setState 异步**: `setUploadProgress` 后不能立即读取新值，React 在下次渲染时才更新
4. **Record 独立追踪**: 不要用全局 `loadCode` 变量，否则所有卡片共享同一个进度值
5. **onload 回调**: 上传完成后需要在 `xhr.onload` 中刷新列表，否则页面不会更新

## 常见错误

| 错误 | 原因 | 修复 |
|------|------|------|
| `'/api/kb/${id}/upload'` 变量不替换 | 单引号是普通字符串 | 改为反引号 `` `/api/kb/${id}/upload` `` |
| 上传完不刷新列表 | 缺少 `xhr.onload` 回调 | 在 onload 中调用刷新函数 |
| 所有卡片进度一样 | 用了全局变量而非 Record | 用 `Record<string, number>` 独立追踪 |
| setState 后读旧值 | setState 是异步的 | 用 useEffect 监听或函数式 setState |
