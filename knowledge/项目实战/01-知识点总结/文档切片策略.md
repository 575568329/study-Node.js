# 文档切片策略（Chunking）

> 学习日期: 2026-05-03 | 置信度: ⭐⭐⭐

---

## 核心概念

文档切片是 RAG 的关键环节，切片质量直接影响搜索召回率。

### 两种策略对比

| 策略 | 优点 | 缺点 |
|------|------|------|
| 纯字符切片 | 简单 | 切断语义，丢失上下文 |
| 标题分段切片 | 保留语义结构 | 长段落仍需二次切片 |

### 最优方案：标题分段 + 固定大小
1. 先按 Markdown 标题（# ~ ######）将文档拆为多个段落
2. 小段落直接作为一个切片
3. 大段落按固定大小切片，带 overlap
4. 所有切片都拼接上所属标题

## 代码示例

```typescript
// chunker.ts 核心逻辑
function chunkText(text: string, chunkSize: number, overlap: number): string[] {
  const sections = splitByHeadings(text)  // 按标题分段

  for (const section of sections) {
    if (section.content.length <= chunkSize) {
      // 小段落直接使用
      chunks.push(withHeading(section))
    } else {
      // 大段落按固定大小切片
      for (let i = 0; i < section.content.length; i += step) {
        chunks.push(withHeading({ heading, content: slice }))
      }
    }
  }
}
```

## 关键要点
1. overlap 保证相邻切片有重叠，避免关键信息被切断
2. 标题是重要的上下文信息，切片不带标题会导致搜索结果无意义
3. chunkSize 需要根据 embedding 模型能力调整（中文建议 800-1500）
4. 标题多的文档（如 API 文档）切片数量会很多，需权衡

## ❌ 常见错误与纠正（复习重点）⚠️

### 错误1：切片过小导致搜索不准
- **错误示例**: chunkSize=500，56 个切片，大部分切片只有几句话
- **错误原因**: 文档标题多、每段内容短，固定大小切片产生大量碎片
- **正确理解**: 标题分段后很多段落本身就小于 chunkSize，调大 chunkSize 对这类文档效果有限，需要混合搜索配合
