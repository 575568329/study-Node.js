# 数据库与持久化取舍

更新时间：2026-05-07

## 结论先行

当前项目阶段的取舍是：

- 本地 JSON / FileStore 适合演示、单机和快速闭环
- SQLite 适合轻量、单机、低成本的业务持久化
- PostgreSQL 适合多人协作、稳定事务和更完整的业务数据管理
- Chroma / pgvector 适合向量检索和更专业的向量数据存储

---

## 1. 为什么现在还能用 JSON？

答题要点：

- 项目目标是快速演示和闭环
- 依赖少，启动简单
- 对个人项目和小规模数据足够

局限：

- 并发写入弱
- 数据量增大后性能不稳
- 不适合多人协作和线上高可用

---

## 2. SQLite 适合什么场景？

答题要点：

- 轻量业务数据存储
- 单机或小团队场景
- 比 JSON 更稳定，结构化更强

面试可说：

- 如果要在当前项目上做第一步持久化升级，我会优先考虑 SQLite

---

## 3. PostgreSQL 适合什么场景？

答题要点：

- 多人协作
- 数据一致性要求高
- 需要复杂查询和事务

面试可说：

- 业务元数据如果进入多人协作或更稳定的线上场景，我会优先选 PostgreSQL

---

## 4. 为什么向量数据不直接和业务数据混在一起？

答题要点：

- 业务数据关注知识库、文档、权限、状态
- 向量数据关注召回、相似度、片段检索
- 两类数据生命周期不同，最好分层存储

---

## 5. Chroma / pgvector 怎么选？

答题要点：

- Chroma：更偏独立向量库，便于快速接入
- pgvector：如果业务已经在 PostgreSQL 里，集成度更高
- 两者都比本地 JSON 更适合正式的向量检索场景

---

## 6. 面试时怎么讲这个取舍？

推荐表达：

```text
当前项目用本地 JSON 和 FileStore 先保证快速闭环和演示成本可控；如果后续进入多人协作或更大规模场景，我会把业务元数据迁到 SQLite 或 PostgreSQL，把向量存储迁到 Chroma 或 pgvector，分层解决业务数据和向量检索两个问题。
```
