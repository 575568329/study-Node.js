# 三版本简历方向调研结论

更新时间：2026-05-05

当前状态：已根据本调研结论重写 React 网页简历三版本，并完成构建验证。

补充状态：已阅读架构师评价，并将可采纳意见合入简历与方案；高风险夸大项仅作为后续补强方向。

## 结论

保留这三个版本是合理的：

1. 通用版
2. 纯前端版
3. Node.js 全栈 AI 版

不单独保留 GIS 可视化版、教育国际化版、独立 AI 应用前端版也是合理的。原因是：GIS 和教育更像你的项目行业背景，不一定适合作为主投职业方向；独立 AI 应用前端和 Node.js 全栈 AI 高度重叠，拆开会稀释简历维护精力。

更稳的策略是：

- 通用版负责大多数岗位。
- 纯前端版负责传统前端岗位。
- Node.js 全栈 AI 版负责 AI 应用、小团队全栈、Next.js / Node.js 岗位。

## 调研依据

### 1. 前端基础盘仍然存在

公开岗位和趋势报告仍然把 React、Vue、TypeScript、工程化、复杂业务交付作为前端核心要求。

可参考：

- OHO Group 的 JavaScript H1 2025 Talent Report 提到，React、Angular、Node.js 仍是招聘计划中的重要技术，React、TypeScript、Node.js 组合需求较高；TypeScript 增长明显。来源：[OHO JavaScript H1 2025 Talent Report](https://www.oho.co.uk/talent-report/javascript-h1-2025-talent-report/)
- InfoQ 对 State of JavaScript 2025 的报道提到，TypeScript 已成为 JavaScript 生态的明显主流方向，React 使用率仍高，Vite 也已成为重要工程化工具。来源：[InfoQ - State of JavaScript 2025](https://www.infoq.com/news/2026/03/state-of-js-survey-2025/)
- 2026 年的 AI Agent 前端岗位仍明确要求 Next.js、React、TypeScript、Tailwind，并强调 UI 组件、企业工作流、实时事件流和可视化。来源：[Restack Frontend Engineer](https://careers.crane.vc/companies/restack/jobs/65375659-frontend-engineer-next-js-react-typescript-forward-deployed)

对应到你：

- 纯前端版必须保留。
- 通用版也必须以前端为主标题，不应默认写成 AI 工程师。
- Vue2 / Vue3、React、TypeScript、Webpack、Vite、OpenLayers、ECharts、WebSocket 仍然是有效关键词。

### 2. Node.js + React / Next.js + TypeScript 的全栈方向是合理增量

现在不少岗位不再只要单纯前端，而是希望前端能处理 API、Node.js、数据层、AI 接口、后台工具和端到端交付。

可参考：

- Cognizant 2026 年 4 月发布的 Senior Full Stack Software Developer 岗位要求 Node.js、React、TypeScript，并写到 RESTful API、前端 UI 组件和生成式 AI / LLM 原型探索。来源：[Cognizant Senior Full Stack Software Developer](https://careers.cognizant.com/apj-en/jobs/00068137471/senior-full-stack-software-developer-nodejs-react-typescript-hybrid/)
- 远程工作者收录的 AI 出海全栈岗位要求 Next.js、Supabase、Node.js、React、TypeScript，并要求使用 AI 编程工具完成从需求分析到代码交付流程。来源：[远程工作者 - 全栈开发 AI 出海产品](https://remote-china.com/jobs/981)
- OHO 报告也提到 full-stack TypeScript、React、TypeScript、Node.js 在创业公司和现代技术栈中有需求。来源：[OHO JavaScript H1 2025 Talent Report](https://www.oho.co.uk/talent-report/javascript-h1-2025-talent-report/)

对应到你：

- Node.js 全栈 AI 版是合理的差异化版本。
- 但它不能写成资深后端，因为你的强项仍是前端和 AI 应用集成。
- 简历标题写“全栈型前端工程师”比“全栈工程师”更稳。
- `rag-docs-assistant` 的 API Route、文件上传、文档解析、向量存储、流式问答，正好能支撑这个方向。

### 3. AI 应用是加分项，但要强调验证和工程质量

AI 工具和 AI 应用需求增长明显，但市场也越来越警惕“只会用 AI 生成代码”的候选人。简历应突出你能审查、验证、落地，而不是强调 AI 写了多少代码。

可参考：

- Stack Overflow 2025 Developer Survey 显示，84% 受访者使用或计划使用 AI 工具，专业开发者中 51% 每天使用 AI 工具；但同时 46% 的开发者不信任 AI 输出准确性，说明“人负责审查和质量把控”是关键。来源：[Stack Overflow 2025 AI Survey](https://survey.stackoverflow.co/2025/ai)
- 远程工作者收录的前端高级岗位明确写到“熟练使用 Coding Agent 辅助编码，并有自己的 AI 工作规范和流程”，同时仍要求 TypeScript、Node.js、React / Electron / 富文本编辑器等工程能力。来源：[远程工作者 - 前端高级开发工程师](https://remote-china.com/jobs/1025)
- Restack 的 AI Agent 前端岗位强调构建和定制企业 AI Agent 工作台、事件流、Prompt 版本 UI、Agent 配置面板，说明 AI 产品前端不是简单聊天框，而是复杂工作台和工程化 UI。来源：[Restack Frontend Engineer](https://careers.crane.vc/companies/restack/jobs/65375659-frontend-engineer-next-js-react-typescript-forward-deployed)

对应到你：

- AI 能力应该进入通用版和 Node.js 全栈 AI 版。
- 不建议单独保留“AI 应用前端版”，因为它和 Node.js 全栈 AI 版高度重叠。
- AI 辅助开发不能写“90% AI 开发”，应写“深度使用 AI 辅助需求拆解、代码生成、问题定位和回归验证，并负责代码审查、业务验证和最终质量把控”。

## 三个版本是否合理

### 通用版：合理，建议作为默认版本

适用场景：

- 岗位描述只写“前端开发工程师”。
- 不确定公司更看重 Vue、React、AI 还是行业经验。
- HR 初筛阶段需要稳定、清楚、不过度包装。

为什么合理：

- 你的真实经历横跨教育出海、GIS、IoT、B 端系统，如果只写某一个方向会浪费素材。
- 通用版能保留完整工作时间线，降低 HR 对经历断层的疑问。
- 加入 RAG 项目可以体现新技术跟进，但不会把主线变成“AI 工程师”。

建议项目：

1. 讯飞智学网澳门国际化项目
2. 智能知识管理平台 / RAG 文档问答系统
3. 甘肃 / 北京地质灾害 GIS 可视化项目

注意：

- 通用版不要写得太满，避免三页以上。
- RAG 项目写成加分项，不要压过真实工作经历。

### 纯前端版：合理，必须保留

适用场景：

- Vue / React 前端。
- B 端管理系统。
- 外包、行业软件、传统业务系统。
- 对 AI 没有明确要求的岗位。

为什么合理：

- 你最强的确定性仍然是前端交付经验。
- 当前市场仍然需要 React / Vue / TypeScript / 工程化 / 复杂业务系统能力。
- 这个版本能最大化降低面试官对“AI 项目是不是学习 demo”的顾虑。

建议项目：

1. 讯飞智学网澳门国际化项目
2. 甘肃 / 北京地质灾害 GIS 可视化项目
3. 上汽车载终端实时数据与跨端项目

注意：

- RAG 项目可以不放，或者只在技能/个人项目里轻量展示。
- 不要让纯前端版看起来像“正在转行 AI，所以前端不稳定”。

### Node.js 全栈 AI 版：合理，但要控制边界

适用场景：

- AI 应用公司。
- Next.js / React / Node.js 岗位。
- 小团队全栈岗位。
- 企业知识库 / RAG / AI 助手项目。

为什么合理：

- 2026 岗位里 Next.js、React、TypeScript、Node.js、AI 工具、AI 产品工程能力经常一起出现。
- `rag-docs-assistant` 已经有真实可讲的工程链路：上传、解析、切片、Embedding、FileStore / Chroma、混合检索、流式回答、来源引用、知识图谱。
- 你的前端复杂系统经验能补足个人 AI 项目的业务可信度。

建议项目：

1. 智能知识管理平台 / RAG 文档问答系统
2. 讯飞智学网澳门国际化项目
3. 甘肃 / 北京地质灾害 GIS 可视化项目

注意：

- 不要写“资深后端”“高并发”“微服务”“分布式”，除非项目真实补齐。
- 后端能力重点写 Next.js API Route、Node.js、文件处理、接口设计、本地持久化、向量存储抽象。
- AI 能力重点写 RAG、Embedding、检索、流式响应、来源引用、质量控制。

## 为什么不保留 GIS 和教育专版

### GIS 专版不保留的原因

GIS 是你的强项目，但不是你的主要长期职业定位。单独做 GIS 版会把投递范围缩窄到地信、应急、地图平台和可视化公司。如果你后续明确投 GIS 公司，可以临时从纯前端版复制一份专项版本，不需要长期维护。

### 教育国际化专版不保留的原因

教育国际化项目非常适合作为工作项目，但“教育国际化前端”岗位本身不是稳定大类。它更适合作为通用版和纯前端版的强项目，而不是单独职业方向。

### AI 应用前端专版不保留的原因

它和 Node.js 全栈 AI 版重叠度太高。与其拆成两个相似版本，不如把 AI 应用能力集中在 Node.js 全栈 AI 版里，表达更清楚。

## 对当前方案的调整建议

1. 版本只保留：通用版、纯前端版、Node.js 全栈 AI 版。
2. 默认打开通用版。
3. 通用版保留完整工作经历，项目用“讯飞 + RAG + 地灾”。
4. 纯前端版保留完整工作经历，项目用“讯飞 + 地灾 + 车载”。
5. Node.js 全栈 AI 版把项目提前，项目用“RAG + 讯飞 + 地灾”。
6. 页面设计可以有颜色，但不要变成作品集首页；要像可打印的工程师 Resume UI。
7. AI 表达强调“可验证项目 + 审查验证能力”，不要强调“AI 写了多少代码”。

## 最终判断

这三个版本是当前阶段最合理的组合。它们覆盖面清楚、维护成本低，也和你的真实素材匹配：

- 通用版：负责最大投递面。
- 纯前端版：负责传统岗位稳定转化。
- Node.js 全栈 AI 版：负责差异化和更高成长性的 AI / 全栈岗位。

后续如果发现某类岗位投递反馈明显更好，再从这三个版本里派生专项版即可，不建议现在维护太多版本。

## 资深 AI 公司面试官补充审阅

如果从互联网 AI 应用公司面试官视角看，当前方案的核心评价是：

**方向对，但需要把 RAG 项目准备到可以现场讲、现场演示、现场追问。**

我会把你的候选人画像归类为：

- 不是纯 AI 工程师。
- 不是资深后端。
- 是有真实复杂前端经验、正在升级到 AI 应用交付的全栈型前端。

这个定位在当前就业形势下是合理的，因为普通前端岗位竞争更激烈，而 AI 应用公司更需要能把模型能力落成产品界面、工作台、上传解析、流式问答、来源引用和后台工具的人。

但我会重点验证三件事：

1. 你是否真的理解 RAG 链路，而不是只把 AI 生成的代码跑起来。
2. 你是否能把复杂业务需求拆成稳定工程实现。
3. 你是否有代码审查、验证、问题定位和上线质量意识。

### 面试官会加分的表达

- “我用 AI 辅助编码，但我负责需求理解、方案判断、代码审查和最终验证。”
- “RAG 项目不是简单聊天框，包含文档解析、切片、向量化、检索、上下文注入、流式回答和来源引用。”
- “Node.js 全栈 AI 版的定位是全栈型前端，不是资深后端；我能完成 AI 应用的端到端闭环。”

### 面试官会扣分的表达

- “代码 90% 都是 AI 写的。”
- “我会 RAG、Agent、知识图谱”，但讲不清具体实现。
- “我能做全栈”，但数据库、鉴权、部署、错误处理都没有准备。
- “AI 项目很完整”，但现场无法运行、没有演示文档、没有 README。

### 当前优先补强项

1. 给 `rag-docs-assistant` 补 README 的项目亮点、架构图和演示步骤。
2. 准备一份 RAG 项目 3 分钟讲稿。
3. 准备一份 RAG 项目追问清单。
4. 网页简历三版本统一蓝色视觉，并做更清晰的项目排序。
5. 导出 PDF 后逐页检查：不截断、不留大空白、不出现页面控件。
