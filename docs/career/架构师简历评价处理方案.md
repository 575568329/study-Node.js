# 架构师简历评价处理方案

更新时间：2026-05-06

## 总体判断

架构师评价的核心问题是对的：当前简历如果只是写“前端开发工程师”，优势不够锋利；如果写 AI / Node.js，又必须能讲清楚具体链路，否则面试会被追问穿。

本轮处理原则：

- 采纳“框架重构、优势前置、项目沉淀方向明确”的建议。
- 不直接采纳容易引发背调或面试风险的夸大表达。
- 简历定位从“普通前端”升级为“全栈型前端 / AI 应用方向前端”，但保留纯前端版本作为稳定投递版本。

## 采纳的建议

### 1. 简历需要框架

处理方式：

- 保留三版：通用版、纯前端版、Node.js 全栈 AI 版。
- 通用版作为默认，强调“复杂业务系统 + AI 应用实践”。
- Node.js 全栈 AI 版项目经历前置，突出 RAG 项目。
- 纯前端版保留真实工作项目，作为传统岗位稳定版本。

### 2. 优势要前置，不只列会什么

处理方式：

- 摘要改为更短、更像优势描述。
- 不再只写“熟悉 Vue / React / TypeScript”，而是写“擅长复杂 B 端、跨系统改造、RAG 应用落地、可视化性能优化”。

### 3. 讯飞项目要突出负责人和沉淀价值

处理方式：

- 工作经历中把角色调整为“前端负责人 / 前端开发工程师”。
- 公司 / 项目表述使用“讯飞智学网项目组（百得思维派驻）”，既突出项目方，也避免背调风险。
- 项目重点收敛到两个沉淀方向：
  - 资源 I18N / 澳门业务参数链路。
  - 富文本公式编辑与展示链路。

### 4. AI 技能要能讲 3-5 分钟

处理方式：

- 不堆 MCP、OpenClaw、LangGraph 等暂未形成项目支撑的关键词。
- 当前简历只写能基于 `rag-docs-assistant` 讲清楚的内容：
  - RAG Pipeline。
  - 文档解析。
  - chunk。
  - 向量检索。
  - 混合检索。
  - SSE / 流式回答。
  - 来源引用。
  - 知识图谱。

### 5. 前端能力要体现组件化和跨端

处理方式：

- 技能区保留 Vue2 / Vue3、React、TypeScript、uni-app、小程序、WebSocket、JS-Bridge。
- 项目中补充“原子组件 / 通用组件 / 业务组件”沉淀表达，但不写成已经独立发布的组件库，除非后续真的补齐组件库项目。

## 谨慎处理的建议

### 1. “直接写科大讯飞”

不直接采纳。

原因：

- 如果劳动关系或合同主体不是科大讯飞，直接写“科大讯飞”有背调风险。

折中写法：

- 工作经历：`讯飞智学网项目组（百得思维派驻）`
- 项目经历：`讯飞智学网澳门市场资源加工与题库国际化改造`

面试解释：

- “我是百得思维派驻到讯飞智学网项目组，负责澳门项目相关前端模块。”

### 2. “都写全栈工程师”

部分采纳。

原因：

- 你的主经验仍然是前端，后端和 AI 项目正在补强。
- 直接写“全栈工程师”会被问后端深度、高并发、数据库、部署、微服务。

折中写法：

- 通用版：`全栈型前端工程师`
- Node.js 全栈 AI 版：`全栈型前端工程师｜React / Next.js / Node.js｜AI 应用方向`
- 纯前端版：保留 `前端开发工程师`

### 3. “写 MCP / OpenClaw / LangGraph”

暂不写进正式简历。

原因：

- 当前项目支撑不足。
- 如果写进简历，必须能讲架构价值、落地范式、核心组件、和项目中的具体使用。

后续补强后可加入：

- MCP：工具协议、资源暴露、工具调用边界。
- LangGraph：状态图、多 Agent 流程、可恢复执行。
- OpenClaw / Devin：架构价值、自动任务拆解、代码执行闭环。

## 下一步补强清单

1. 给 `rag-docs-assistant` 补项目架构图。
2. 准备 RAG 项目 3 分钟讲稿。
3. 准备 AI 技能追问清单。
4. 做一个小型组件库或至少在简历项目中沉淀“业务组件拆分案例”。
5. 准备 Node.js 后端基础追问：IoC、Java Bean 类比、队列、SSE、WebSocket、任务队列、文件处理。
6. 暂不把 MCP / LangGraph / OpenClaw 写进正式简历，等能讲清楚后再升级 Node.js 全栈 AI 版。
