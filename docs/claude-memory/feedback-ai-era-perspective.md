# AI 时代视角板块

> ⚠️ **跨设备权威来源 = 项目 `CLAUDE.md`「会话追踪」开头**（2026-07-30 迁入，随 git 跨设备生效）。
> 本 memory 是本机快速召回 + 详细示例，规范以 CLAUDE.md 为准；两处若冲突，改 CLAUDE.md。

## 背景

用户在进行**前端复习线**（费曼学习法）产出面试讲稿时，每个技术点（Q1/Q2/Q3...）都包含以下固定板块：
- 3分钟主讲稿
- 可能的追问
- **🤖 AI时代视角**（本 memory 重点）
- 我曾经的盲区

## 为什么需要这个板块

在 AI 辅助开发（Claude/Copilot/Cursor）普及的 2026 年，技术点的价值需要重新审视：
- **哪些被 AI 降维**：AI 能生成的代码/工具函数，人类只需会用
- **哪些仍需人类**：架构决策、权衡取舍、业务理解、系统设计
- **如何与 AI 协作**：人类负责 What/Why，AI 负责 How

## 板块内容要求

每个技术点的"🤖 AI时代视角"应回答：
1. **AI 能做什么**：这个技术点 AI 能自动生成/优化到什么程度
2. **人类仍需什么**：哪些决策/理解/权衡 AI 做不了或做不好
3. **协作方式**：如何发挥各自优势

## 示例（来自 Node.js 讲稿 Q5 JWT）

```markdown
### 🤖 AI时代视角

**AI 能做**：
- 生成 JWT sign/verify 工具函数（HMAC 签名、base64url 编码）
- 生成双 token 刷新逻辑模板

**人类仍需**：
- **签名 vs 加密的概念区分**（AI 可能混淆）
- **主动失效的系统设计权衡**（黑名单 vs 短过期 vs 版本号，需结合业务场景决策）
- **安全风险评估**（secret 泄露、XSS 攻击 token、HTTPS 必要性）

**协作方式**：
- 人类：设计认证架构（选 Session/JWT/OAuth2）、定安全策略、评估风险
- AI：生成实现代码、补全边界场景、优化性能
```

## 示例（来自 Node.js 讲稿 Q6 CORS）

```markdown
### 🤖 AI时代视角

**AI 能做**：
- 生成 CORS 中间件配置（Express cors、白名单逻辑）
- 诊断 CORS 报错（读 Network 面板 OPTIONS 状态）

**人类仍需**：
- **为什么需要 CORS**（CSRF 攻击原理、同源策略设计动机）
- **简单请求 vs 预检请求的边界判断**（Content-Type/自定义头触发预检的业务影响）
- **安全配置决策**（`*` 的风险、是否需要 credentials、预检缓存时长）

**协作方式**：
- 人类：定跨域策略（哪些域名可访问、是否带 Cookie）、理解浏览器安全模型
- AI：写配置代码、补全 preflight 处理、优化响应头
```

## Why（为什么需要记忆）

- **跨设备一致性**：用户在不同设备（台式机/笔记本）或不同学习线（Java/前端复习/CCode）进行学习时，都应该产出包含此板块的讲稿
- **避免遗忘**：本次对话中临时加上了这个板块，但如果不固化到 memory，下次学习其他技术点时可能忘记加
- **面试差异化**：2026 年面试中，能清晰区分"AI 能做的"和"人类不可替代的"，体现更高认知层次

## How to apply（如何应用）

当进行**前端复习线**或任何技术点讲稿产出时：
1. 检查讲稿模板是否包含"🤖 AI时代视角"板块
2. 如果没有，主动补充
3. 内容聚焦：AI 能做 + 人类仍需 + 协作方式

**适用范围**：
- 前端复习线（JS/TS/Vue3/React/CSS/Node.js）✅
- Java 学习线（Spring/MyBatis/Dubbo）✅
- CCode 线（LangChain/MCP/Agent）✅
- 任何技术讲稿/面试准备 ✅

**不适用**：
- 临时代码调试
- 进度记录文件（latest-session/todo）
- Git commit message
