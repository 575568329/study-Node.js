# Node后端追问清单

更新时间：2026-05-11

## 使用方式

这份文档只保留面试中最常追问的后端基础点，默认围绕当前 RAG 项目和全栈交付场景展开。

---

## 1. 为什么把后端能力拆成 API Route？

答题要点：

- 跟 Next.js App Router 的项目结构一致
- 前后端同仓库，接口和页面能一起迭代
- 适合快速搭建工作台、上传、问答、图谱这类业务接口

---

## 2. 文件上传链路你怎么设计的？

答题要点：

1. 先校验知识库是否存在
2. 再校验文件类型、大小、空文件、同名重复
3. 解析成纯文本
4. 切片
5. 批量 embedding
6. 写入向量库
7. 保存文件和文档元数据
8. 异步做图谱抽取

---

## 3. 为什么图谱抽取放异步？

答题要点：

- 图谱属于增强链路
- 不能阻塞上传和问答主流程
- 失败后只影响图谱，不影响入库和检索

---

## 4. 为什么要做错误处理和日志？

答题要点：

- 面向面试：能说清问题定位路径
- 面向线上：能快速判断失败发生在哪一层
- 面向演示：能解释为什么上传成功但图谱失败

日志建议分层：

- 请求入参
- 检索范围
- 搜索结果
- LLM 输出
- 异步任务结果

---

## 5. API 校验为什么不能只靠手写 if？

答题要点：

- 小项目能跑，不代表结构化
- 参数越多，手写判断越容易散
- 更稳的方案是 schema 校验 + 统一错误响应

面试里可以顺带提：

- Zod / Valibot 这类 schema
- 统一 error helper
- 统一 status code 和 message

---

## 6. Node.js 项目里怎么理解“异步任务”？

答题要点：

- 主链路负责立即返回结果
- 增强链路负责补充能力
- 异步任务失败要可隔离、可追踪、可重试

---

## 7. 面试官问你“Node 后端你最常写什么”，怎么答？

答题要点：

- API Route 设计
- 上传和文件校验
- 数据持久化
- SSE 流式输出
- 错误处理和日志
- 与前端联动的业务接口

---

## 8. Node.js 里异步错误处理你一般怎么做？

答题要点：

- 先区分关键主链路和后台增强链路
- 关键链路必须 `await`，再由当前 `try...catch` 统一收口
- 后台增强任务可以不 `await`，但必须 `.catch()`，记录日志并更新任务状态
- `return promise` 不会被当前函数内部 `catch` 捕获，`return await promise` 可以
- 多个缺一不可的并行任务用 `Promise.all`
- 允许部分失败的增强数据用 `Promise.allSettled`
- 大批量异步任务要做并发控制，避免打满数据库连接或下游接口

项目关联：

- RAG 上传主链路：解析、切片、向量化必须能被接口或任务状态捕获失败
- 图谱抽取：可作为后台增强任务，但失败时要记录为 `graph_failed`
- 文件批处理或批量 embedding：不能无脑 `Promise.all`，需要分批或 `p-limit`
