### 🟡 P1 级：运维基础技能（必须了解）

**标准**：不会这些就无法部署、调试、排查问题

#### Linux 系统操作 ⭐⭐⭐⭐⭐（必学）

**为什么是 P1 而不是 P0？**
- 开发阶段用本地 Windows/Mac 就够
- 但部署、排查问题、看日志都需要 Linux
- 不需要精通，但必须会基本操作

**学习深度**：
- ✅ **必须会**：30 个常用命令
- ✅ **必须会**：查日志、看进程、测端口
- 🔶 **了解即可**：Shell 脚本、系统调优
- ❌ **不用学**：内核、驱动、底层原理

**必须掌握的 30 个命令**：

```bash
# 文件操作（10个）
ls -lh          # 查看文件列表
cd /path        # 切换目录
pwd             # 当前目录
cp file dest    # 复制
mv file dest    # 移动/重命名
rm -rf dir      # 删除（危险！）
cat file        # 查看文件
tail -f log     # 实时查看日志（最常用）
grep "ERROR" log # 过滤日志
find . -name "*.log" # 查找文件

# 编辑文件（3个）
vi file         # 编辑（会基本操作即可）
  i             # 进入编辑模式
  :wq           # 保存退出
  :q!           # 不保存退出

# 进程管理（5个）
ps aux | grep java   # 查找 Java 进程
kill -9 <pid>        # 强制杀进程
nohup java -jar app.jar &  # 后台启动
jps                  # 查看 Java 进程
top                  # 实时监控

# 网络调试（5个）
curl http://api      # 测试接口
telnet host port     # 测试端口连通性
netstat -tuln        # 查看端口占用
ping host            # 测试网络
ifconfig / ip addr   # 查看 IP

# 资源监控（4个）
df -h                # 磁盘空间
du -sh dir           # 目录大小
free -m              # 内存使用
top / htop           # CPU/内存监控

# 权限管理（3个）
chmod 755 file       # 修改权限
chown user:group file # 修改所有者
sudo command         # 以 root 执行
```

**学习方式**：
1. 第一遍：跟着教程敲一遍（1天）
2. 第二遍：在服务器上实操（2天）
3. 第三遍：整理速查表，遇到就查（持续）

**验收标准**：
- [ ] 能 SSH 登录服务器
- [ ] 能查看 Java 应用日志并过滤错误
- [ ] 能重启 Java 应用
- [ ] 能测试接口和端口连通性
- [ ] 能查看服务器资源使用情况

#### Docker 容器化 ⭐⭐⭐⭐（强烈推荐）

**为什么要学？**
- 现代 Java 开发的标准部署方式
- 本地开发环境统一（MySQL/Redis/Zookeeper）
- 简历加分项（证明你懂现代技术栈）

**学习深度**：
- ✅ **必须会**：Docker 基础命令、Dockerfile 编写
- ✅ **必须会**：Docker Compose 多服务编排
- 🔶 **了解即可**：镜像优化、网络模式
- ❌ **不用学**：Docker 源码、底层实现

**必须掌握的操作**：

```bash
# 镜像操作（5个）
docker pull mysql:8.0           # 拉取镜像
docker images                   # 查看镜像
docker rmi <image_id>           # 删除镜像
docker build -t app:v1 .        # 构建镜像
docker tag app:v1 repo/app:v1   # 打标签

# 容器操作（10个）
docker run -d -p 3306:3306 mysql  # 启动容器
docker ps                         # 查看运行容器
docker ps -a                      # 查看所有容器
docker stop <container_id>        # 停止容器
docker start <container_id>       # 启动容器
docker restart <container_id>     # 重启容器
docker rm <container_id>          # 删除容器
docker logs -f <container_id>     # 查看日志
docker exec -it <container_id> bash # 进入容器
docker inspect <container_id>     # 查看容器信息

# Compose 操作（5个）
docker-compose up -d              # 启动服务栈
docker-compose ps                 # 查看服务状态
docker-compose logs -f app        # 查看服务日志
docker-compose restart app        # 重启服务
docker-compose down               # 停止并删除
```

**Dockerfile 示例**（必须会写）：

```dockerfile
# 基础镜像
FROM openjdk:8-jdk-alpine

# 设置工作目录
WORKDIR /app

# 复制 jar 包
COPY target/app.jar app.jar

# 暴露端口
EXPOSE 8080

# 启动命令
ENTRYPOINT ["java", "-jar", "app.jar"]
```

**Docker Compose 示例**（必须会写）：

```yaml
version: '3.8'

services:
  app:
    build: .
    ports:
      - "8080:8080"
    depends_on:
      - mysql
      - redis
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/db

  mysql:
    image: mysql:8.0
    ports:
      - "3306:3306"
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: db
    volumes:
      - mysql-data:/var/lib/mysql

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  mysql-data:
```

**学习方式**：
1. 安装 Docker Desktop（1天）
2. 跑通官方示例（1天）
3. 容器化自己的 Spring Boot 项目（2天）
4. 用 Compose 编排完整开发环境（2天）

**验收标准**：
- [ ] 能用 Docker 运行 MySQL/Redis
- [ ] 能写 Dockerfile 构建 Java 应用镜像
- [ ] 能用 Docker Compose 编排多服务
- [ ] 能解释"容器化解决了什么问题"

#### CI/CD 持续集成 ⭐⭐⭐（了解概念）

**为什么优先级不高？**
- 公司有专门运维团队配置好了
- 开发只需要会用，不需要从零搭建
- 面试时能讲清楚流程就够

**学习深度**：
- ✅ **必须会**：理解 CI/CD 概念和流程
- ✅ **必须会**：会用 Git 触发构建
- 🔶 **了解即可**：Jenkins/GitLab CI 配置
- ❌ **不用学**：Jenkins 插件开发

**必须理解的概念**：

```
CI/CD 流程：
1. 开发提交代码到 Git
   ↓
2. 触发 CI 构建（Webhook）
   ↓
3. 拉取代码 + 编译 + 测试
   ↓
4. 构建 Docker 镜像
   ↓
5. 推送镜像到仓库
   ↓
6. 部署到测试/生产环境
   ↓
7. 健康检查 + 通知
```

**Jenkins Pipeline 示例**（能看懂即可）：

```groovy
pipeline {
    agent any
    
    stages {
        stage('拉取代码') {
            steps {
                git 'https://github.com/user/repo.git'
            }
        }
        
        stage('Maven 构建') {
            steps {
                sh 'mvn clean package -DskipTests'
            }
        }
        
        stage('Docker 构建') {
            steps {
                sh 'docker build -t app:${BUILD_NUMBER} .'
            }
        }
        
        stage('部署') {
            steps {
                sh 'docker-compose up -d'
            }
        }
    }
    
    post {
        success {
            echo '部署成功！'
        }
        failure {
            echo '部署失败！'
        }
    }
}
```

**学习方式**：
1. 理解概念（1天）
2. 看公司 CI/CD 配置（1天）
3. 了解 Jenkins/GitLab CI（1天）

**验收标准**：
- [ ] 能画出 CI/CD 流程图
- [ ] 能解释"自动化部署的好处"
- [ ] 能看懂公司的 Pipeline 配置
- [ ] 面试时能讲清楚流程

### 🟢 P2 级：Kubernetes（可选）

**为什么是 P2？**
- ❌ 学习曲线陡峭（概念多、上手难）
- ❌ 中小公司不一定用（Docker Compose 够用）
- ❌ 运维负责 K8s 集群，开发只写配置
- ❌ 1个月内学不精，性价比低

**什么时候学？**
- ✅ 入职后公司用了 K8s，边用边学
- ✅ 求职大厂时突击 2 周概念
- ✅ 有精力可以第 5-6 个月补

**最低要求（面试够用）**：

```yaml
# 能看懂这个配置即可
apiVersion: apps/v1
kind: Deployment
metadata:
  name: spring-boot-app

    metadata:
      labels:
        app: spring-boot
    spec:
      containers:
      - name: app
```

**面试话术**：

### Linux

### Docker

**面试官**："你项目是怎么部署的？"

**回答**：
> "我用 Docker 容器化部署。写了 Dockerfile 构建 Spring Boot 镜像，用 Docker Compose 编排应用 + MySQL + Redis，本地开发和测试环境都用 Docker 统一。这样避免了'我这能跑你那不能跑'的问题，也方便持续集成。"

---

### CI/CD

**面试官**："你了解 CI/CD 吗？"

**回答**：
> "了解。CI/CD 是持续集成和持续部署，核心思想是自动化。流程是：开发提交代码 → Git Hook 触发 Jenkins → Maven 构建 → Docker 打镜像 → 部署到测试/生产环境。我之前用 Jenkins 配置过自动化构建，代码 push 后自动跑测试、打包、部署。这样能快速发现问题，提高交付效率。"

---

### Kubernetes

**面试官**："你们用 K8s 吗？"

**回答**：
> "目前项目还没用 K8s，用的是 Docker Compose。我了解 K8s 的核心概念，知道它是容器编排平台，解决了大规模容器部署、自动扩缩容、服务发现的问题。如果公司用 K8s，我可以快速学习配置文件的编写和部署流程。"

## 常见误区

### ❌ 误区 1：运维技能要精通才能找工作

**真相**：开发岗不是运维岗，会基本操作就够。

- 公司有专门运维团队
- 开发只需要会部署、调试、排查问题
- Linux 30 个命令 > 深入内核原理

---

### ❌ 误区 2：Docker/K8s 必须学，不学就落伍

**真相**：Docker 推荐学（投入产出比高），K8s 可选学（看公司）。

- Docker：学习成本低，实用性高
- K8s：学习成本高，不一定用得上
- 优先级：Docker ⭐⭐⭐⭐⭐ > K8s ⭐⭐

---

### ❌ 误区 3：看视频教程 = 学会了

**真相**：运维技能必须实操，看 100 遍视频不如上手 1 次。

- Linux：必须在服务器上敲命令
- Docker：必须自己构建镜像、编排服务
- CI/CD：必须搭一次 Jenkins Pipeline

---

### ❌ 误区 4：运维技能和开发技能分开学

**真相**：运维技能是为开发服务的，边开发边学最高效。

- 学 Spring Boot → 立即 Docker 化
- 学数据库 → 立即用 Docker 运行 MySQL
- 学微服务 → 立即用 Compose 编排

## 总结

### 必学（P0 + P1）

| 技能 | 学习时长 | 深度 | 验收标准 |
|------|---------|------|----------|
| Java + Spring | 10周 | 精通 | 能独立开发接口 |
| Linux | 1周 | 会用 | 能部署排查问题 |
| Docker | 1周 | 熟练 | 能容器化项目 |

### 可选（P2）

| 技能 | 学习时长 | 深度 | 何时学 |
|------|---------|------|--------|
| CI/CD | 3天 | 了解 | 第 15 周 |
| K8s | 2天 | 概念 | 入职后或求职大厂时 |

### 时间分配

- 70% 时间：核心开发技能（Java/Spring/数据库/微服务）
- 20% 时间：运维基础（Linux/Docker/CI/CD）
- 10% 时间：实战项目整合

### 关键建议

1. **不要被技能清单焦虑**：按需学习，够用就行
2. **优先实操，再理解原理**：先会用，再深入
3. **运维技能为开发服务**：边写代码边部署
4. **K8s 不是必选项**：入职后再学不晚
