# 组件库组件范围说明

更新时间：2026-05-07

## 目的

`fullstack-ui-kit` 不是做一个通用 UI 大而全组件库，而是做一个**围绕 AI 应用、RAG 工作台、项目沉淀和前端复杂状态**的小型组件库。

这个库的目标不是替代 Ant Design，也不是覆盖所有基础控件，而是把真实项目里高复用、强场景、可讲解的内容沉淀下来，作为简历和面试的技术证明。

## 设计原则

1. 只抽能复用、能讲清楚、能在项目里反复出现的组件。
2. 优先抽 AI / RAG / Agent / 流式交互相关组件。
3. 优先抽前端疑难场景组件，例如流式渲染、异步状态、错误恢复、重试、取消、历史回放。
4. 普通 UI 控件只保留最小能力，不把精力浪费在“谁都已经会做”的基础按钮和输入框上。
5. 所有组件都要能说明它对应哪个真实业务场景，不能为了像组件库而组件库。

## 重点组件范围

### 1. AI 对话类

这类组件用于表达 ChatGPT 类、RAG 类交互。

- `ChatMessage`
- `MessageBubble`
- `ConversationList`
- `PromptComposer`
- `StreamingText`
- `ThinkingIndicator`

适合表达的能力：

- 用户消息和助手消息分层展示。
- 流式输出中的增量文本渲染。
- 生成中、完成、失败等状态展示。
- 会话历史的聚合和回放。

### 2. RAG 来源与引用类

这类组件用于表达“回答为什么是这个答案”。

- `SourceCard`
- `CitationList`
- `RagScoreBadge`
- `ContextSnippet`
- `DocumentPreviewCard`

适合表达的能力：

- 文件名、片段、来源位置、相关性分数展示。
- 把检索结果和回答结果绑定起来。
- 帮面试官快速理解 RAG 链路。

### 3. Agent / 流程展示类

这类组件用于表达工作流、工具调用和执行过程。

- `StepTimeline`
- `ToolCallPanel`
- `ActionTrace`
- `StatusPill`
- `ExecutionLogPanel`

适合表达的能力：

- pending / running / success / error 状态。
- 工具调用过程展示。
- Agent 执行步骤回放。
- 适合和 LangGraph、任务流、调试面板一起讲。

### 4. 项目沉淀类

这类组件来自真实项目中最重要的业务复用点。

- `UploadPanel`
- `FileStatusList`
- `KnowledgeBaseCard`
- `ConversationHistoryPanel`
- `ErrorStatePanel`
- `RetryNotice`

适合表达的能力：

- 文件上传、进度、失败重试。
- 知识库卡片和会话历史。
- 错误态兜底和恢复入口。
- 业务页面里经常重复出现的交互结构。

### 5. 前端疑难杂症类

这类组件用于沉淀复杂前端问题的处理方式。

- `SseStreamViewer`
- `AbortableActionBar`
- `DebouncedSearchBox`
- `AsyncStateView`
- `EmptyLoadingErrorShell`
- `KeyboardTrapModal`

适合表达的能力：

- SSE 流式处理。
- 请求取消和中断。
- 防抖查询。
- 加载、空态、错误态三态封装。
- 弹窗焦点管理等复杂交互。

## 不作为重点的普通组件

下面这些组件不是不能做，而是**不作为这个项目的主卖点**。

- `Button`
- `Input`
- `Modal`
- `Toast`
- `Tabs`
- `Table`
- `Form`
- `Pagination`
- `Sidebar`
- `Header`

原因很简单：

1. 这些组件太常规，竞争力不在“写出来”，而在“有没有更高价值的场景组件”。
2. 你当前的目标是做项目证明，不是补一个平庸的通用 UI 库。
3. 如果时间有限，优先把 AI 和复杂状态相关组件做深做透。

## 推荐优先级

### P0

第一批必须先做的组件：

- `ChatMessage`
- `SourceCard`
- `StepTimeline`
- `UploadPanel`

这些组件最能体现 AI 场景和项目沉淀价值。

### P1

第二批建议补的组件：

- `ConversationHistoryPanel`
- `StreamingText`
- `ErrorStatePanel`
- `RetryNotice`

这些组件能把前端复杂状态补完整。

### P2

第三批再考虑的组件：

- `MessageBubble`
- `CitationList`
- `ExecutionLogPanel`
- `AsyncStateView`

这些组件更多是增强表达完整性，不是最先要做的。

## 组件库的定位边界

这个库要始终记住三件事：

1. 它服务的是 AI 应用和 RAG 工作台。
2. 它沉淀的是项目里最值得讲的复用能力。
3. 它展示的是前端复杂交互和状态管理，不是基础 UI 体力活。

## 简历表达方向

如果这个库第一阶段做完，简历里更适合这样写：

```text
沉淀 React + TypeScript 组件库，围绕 AI 对话、RAG 来源引用、Agent 执行步骤和文件上传等高频场景进行组件抽象，封装 ChatMessage、SourceCard、StepTimeline、UploadPanel 等组件，提升业务页面复用性与复杂状态处理能力。
```

## 面试可讲重点

- 为什么不做通用大而全组件库。
- 为什么优先抽 AI / RAG / Agent 相关组件。
- 为什么组件要按场景分层而不是按控件类型堆砌。
- 为什么 `UploadPanel`、`SourceCard`、`StepTimeline` 更有项目证明价值。
- 前端复杂状态如何封装成可复用组件。
