# 业务与技术待澄清清单（面试加分项自查）

## 1. 软件工程流程类（找测试/负责人交流）
- [ ] **代码覆盖率**：我们目前的单元测试或集成测试覆盖率标准是多少？（例如：核心逻辑要求 80% 以上吗？）
- [ ] **发布前验证方式**：澳门功能上线前，我实际做的是手动点击页面、走业务路径验证（本质是冒烟/回归测试）。需确认：团队有没有正式的提测/冒烟 Checklist？验证范围和通过标准是什么？
- [ ] **发布与回滚策略**：澳门功能是直接全网发布，还是有分批/灰度？如果有灰度，比例怎么分配（5% -> 20% -> 全量）？出问题怎么回滚？
- [ ] **概念辨析（自查，别用错词）**：A/B 测试 = 随机分流对比两个方案效果（看转化率/点击率等业务指标，做产品决策）；灰度发布 = 新版本小流量逐步放量（看错误率/性能，降低风险）；蓝绿部署 = 两套环境瞬间切换（不停机 + 快速回滚）。我做的属于「上线前手动业务验证」，不是 A/B 测试，简历和面试都不要写「负责 A/B 测试」。

## 2. 国际化与渲染性能（技术自查/验证）
- [ ] **布局崩坏案例**：找一个典型的葡语超长文本导致 UI 错位的截图，尝试用 CSS `text-overflow`, `flex-shrink` 或动态 `font-size` 给出通用解法。
- [ ] **MathJax 性能**：如果页面有 100 道含公式的题目，MathJax 渲染会变慢吗？是否可以尝试“只渲染当前视窗内的公式”（Intersection Observer）？
- [ ] **自动划题逻辑**：去了解一下后端或 AI 引擎是如何识别题目边界的？（是用坐标定位还是语义识别？）

## 3. 自动化与脚本（自我沉淀）
- [ ] **Node.js 大文件处理**：学习一下如何使用 `fs.createReadStream` 处理超过 500MB 的 Excel 或 JSON 数据，防止内存溢出。
- [ ] **PageAgent 调研**：尝试用 PageAgent 或类似的 AI 工具跑一个简单的 UI 自动化测试脚本，验证它是否能发现多语言布局问题。
