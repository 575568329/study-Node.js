# RAG项目演示脚本

更新时间：2026-05-07

## 目标

这份脚本用于：

1. 自己演示项目时不漏步骤
2. 面试中快速组织项目展示顺序
3. 后续录屏或现场讲解时复用

---

## 演示前准备

### 环境

- 项目路径：`D:\Study\rag-docs-assistant`
- 启动命令：

```bash
npm run dev
```

- 访问地址：`http://localhost:3000`

### 演示资料建议

建议准备 3 类文档：

1. 专业制度 / 说明类文档
   适合问定义、流程、职责

2. 结构化表格类文档
   适合问统计、字段、名单、配置项

3. 可抽实体关系的描述类文档
   适合切到图谱页展示实体关系

## 5分钟演示流程

### 第一步：开场介绍

话术：

```text
这个项目是一个 AI 知识库问答系统，主要解决专业资料分散、查找效率低的问题。用户上传文档后，系统会做解析、切片和向量化入库；提问时先检索相关片段，再交给大模型生成答案，并返回来源引用。
```

### 第二步：展示知识库和文档入库

操作：

1. 进入 `数据` 页
2. 创建一个知识库
3. 上传 1 到 2 份文档
4. 展示文档列表、文档数、切片数

要讲的点：

- 支持多格式文档
- 上传后会统一解析成文本
- 再做切片和向量化
- 原始文件也会保留，便于来源回查

### 第三步：展示单知识库问答

操作：

1. 选中某个知识库
2. 切到 `对话` 页
3. 提一个边界明确的问题

建议问题：

- “这份制度文档里关于值班职责的要求是什么？”
- “这个设备表格里一共有哪几类监测设备？”

要讲的点：

- 当前只在单个知识库内检索
- 回答后会返回来源片段
- 可以解释单知识库模式更强调精度

### 第四步：展示全部知识库问答

操作：

1. 左侧切换到 `全部`
2. 提一个跨资料关联问题

建议问题：

- “如果我要同时了解设备类型和维护周期，应该关注哪些文档内容？”
- “不同资料里关于预警和应急处置有哪些关联信息？”

要讲的点：

- 当前全部模式是跨所有知识库统一检索
- 适合跨库联动问题
- 这是当前能力，后续计划加 AI 路由进一步缩小范围

### 第五步：展示来源引用

操作：

1. 展开 `SourceCard`
2. 展示知识库名称、文件名、章节、相关分数

要讲的点：

- `sources` 不是装饰功能
- 它解决了答案可追溯和可信度问题
- 调试时也能判断问题是检索层还是生成层

### 第六步：展示图谱页

操作：

1. 切到 `图谱` 页
2. 展示节点数、边数、搜索和节点详情

要讲的点：

- 图谱抽取是上传后的异步增强链路
- 不阻塞主入库和问答功能
- 当前图谱主要用于可视化和知识浏览，还没进入问答主链路

## 面试时可主动补一句的点

```text
这个项目当前已经把文档入库、RAG 检索、流式回答和来源追溯做成闭环；后续如果继续升级，我会优先补全部模式下的 AI 路由，以及更适合多人和大规模场景的存储方案。
```

---

## 演示时最容易被追问的问题

1. 为什么不能直接把文档整篇交给大模型？
2. 为什么要返回 `sources`？
3. 全部模式为什么不先判断查哪个知识库？
4. 为什么图谱抽取不阻塞上传？
5. 本地 JSON / FileStore 的局限是什么？

---

## 演示中的禁区

1. 不要把“全部模式 AI 路由”说成当前已完成能力
2. 不要把图谱展示说成完整 GraphRAG
3. 不要把本地 JSON / FileStore 说成生产级方案
4. 不要把项目说成已具备权限系统和多租户能力
