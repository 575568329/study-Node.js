# 学习进度更新器

## 概述

自动化Node.js学习进度记录，从会话上下文中提取学习成果并更新3个核心文件。避免重复手动操作，确保记录质量和格式一致性。

## ⚠️ 重要：错误记录优先级（复习重点）

**为什么错误记录如此重要？**

学习过程中，错误是比正确内容更有价值的复习资料：
1. ✅ **错误反映理解偏差**：知道哪里容易错，才能避免重复犯错
2. ✅ **错误原因更深层**：理解错误原因，才能真正掌握概念
3. ✅ **复习效率更高**：重点看错误部分，节省复习时间
4. ✅ **避免盲目自信**：只记录正确内容，容易误以为都掌握了

**错误记录原则**：
- ❌ 不可跳过：会话中的任何错误都必须记录
- ❌ 不可简化：必须记录完整（错误内容、原因、纠正方法、易错点）
- ✅ 优先级高：错误记录比其他内容更重要
- ✅ 复习重点：复习时优先看"常见错误"部分

## 使用时机

用户说以下任一关键词时触发：
- "记录一下进度"
- "更新进度"
- "记录学习成果"
- "记录今日学习"
- "更新学习进度到XX%"

**不要使用**：
- 普通聊天对话
- 非学习相关的记录

## 核心流程

```
用户触发 → 提取信息 → 同步Obsidian → 检查完整性 → 更新4个文件 → 清理todo → 输出总结
```

**重要**：必须先同步Obsidian笔记，检查完整性，再更新其他文件！

## 信息提取清单

### 1. 学习成果
- **新增主题**: 识别今日学习的主题（B.1、C.4、A.2等）
- **完成领域**: 判断哪些领域达到100%（10/10、8/8、12/12等）
- **学习时长**: 估算学习时长（基于会话轮次和内容复杂度）
- **进度变化**: 计算进度提升（如78% → 88%）

### 2. 关键内容
- **学生问题**: 记录所有学生提出的问题（尽可能原文）
- **初始理解**: 记录学生对概念的初始理解
- **讲解方法**: 使用的教学方法（对比、图解、实例、类比等）
- **理解检查**: 验证理解的题目和学生的回答
- **知识漏洞**: 识别的学习漏洞和理解偏差

### 2.5 错误内容提取（重要！复习重点）⚠️
- **错误回答**: 记录学生在理解检查中的错误回答（原文）
- **误解分析**: 分析学生为什么会产生这个误解
- **纠正过程**: 记录如何纠正学生的错误理解
- **常见错误模式**: 识别重复出现的错误类型（如概念混淆、语法错误、逻辑错误）
- **易错点**: 标记每个主题的易错知识点（如："async/await混用"、"Promise链断裂"）
- **错误根源**: 分析错误的根本原因（概念不清、语法不熟、思维惯性）

### 3. 表现评估
- **理解能力**: 对复杂概念的理解程度
- **学习速度**: 学习效率（主题数/小时）
- **优秀表现**: 做得好的地方（诚实、深入理解、举一反三）
- **改进建议**: 需要提升的地方（如果有）

## 常见错误

### ❌ 错误1：缺少学生原始问题
**错误做法**：只记录讲解内容
**正确做法**：记录学生提出的所有问题（尽可能原文）

### ❌ 错误2：缺少理解检查
**错误做法**：只讲解不验证
**正确做法**：讲解后立即提问验证理解

### ❌ 错误3：缺少评估
**错误做法**：只记录内容不评估表现
**正确做法**：评估理解能力、学习速度、优秀表现

### ❌ 错误4：跳过完整性检查
**错误做法**：直接更新文件，不检查笔记是否遗漏
**后果**：出现"已学习但缺笔记"的情况
**正确做法**：必须先检查完整性，确保100%对应

### ❌ 错误5：创建空白笔记
**错误做法**：只创建标题，内容为空
**后果**：笔记无用，无法复习
**正确做法**：填充完整的笔记内容（核心概念、关键要点、练习题）

### ❌ 错误6：不同步到Obsidian
**错误做法**：只在本地记录，不同步到Obsidian
**后果**：多设备无法共享，Git备份缺失
**正确做法**：每次学习后立即同步Obsidian并Git提交

### ❌ 错误7：不记录学习过程中的错误（严重！）⚠️
**错误做法**：只记录正确理解，不记录错误回答
**后果**：复习时无法看到易错点，容易重复犯错
**正确做法**：必须提取会话中的所有错误，记录到笔记的"常见错误"部分
**优先级**：高（错误是复习重点，比正确内容更重要）

### ❌ 错误8：错误记录不完整
**错误做法**：只记录错误内容，不分析原因和纠正方法
**后果**：不知道为什么错，如何避免
**正确做法**：完整记录：错误内容 → 错误原因 → 正确理解 → 如何避免 → 易错点

## 📋 完整性检查清单

### 每次更新进度时必须执行：

**检查1：主题对比**
- [ ] 从tracker.md提取已掌握主题列表
- [ ] 遍历Obsidian笔记库，检查每个主题是否有笔记
- [ ] 记录缺失的主题

**检查2：内容验证**
- [ ] 每个笔记是否有学习日期
- [ ] 每个笔记是否有核心概念解释
- [ ] 每个笔记是否有关键要点（3-5个）
- [ ] 每个笔记是否有练习题或代码示例
- [ ] 标记内容不完整的笔记

**检查2.5：错误记录验证（重要！）⚠️**
- [ ] 扫描会话历史，识别所有错误回答和误解
- [ ] 检查每个笔记是否有"常见错误"部分
- [ ] 验证错误记录的完整性（错误内容、错误原因、正确理解、如何避免）
- [ ] 标记错误记录缺失或不完整的笔记
- [ ] **优先级：高**（错误是复习重点，不能遗漏）

**检查3：Git同步**
- [ ] 检查Obsidian仓库是否有未提交的更改
- [ ] 执行git status确认
- [ ] 执行git add、commit、push

**检查4：生成报告**
- [ ] 生成完整性报告
- [ ] 列出缺失笔记
- [ ] 列出不完整笔记
- [ ] **列出错误记录缺失的笔记（单独标注）**
- [ ] 计算完整性百分比

**检查5：补全操作**
- [ ] 为缺失的主题创建笔记
- [ ] 补充不完整笔记的内容
- [ ] **优先补充错误记录部分（从会话历史提取）**

- [ ] 再次检查直到100%完整
