## 2026-07-15 学习记录

**啃下 JS 最硬的一条链**：闭包 → 原型链 → new → this → call/apply/bind → 事件循环 → Promise 手写（进行中）

**过关题目**（7 题完整 + 1 题进行中）：
1. ✅ Q1 闭包：定义、Vue3 ref、React useState 陷阱、防抖节流、setTimeout/事件监听
2. ✅ Q2 原型链：prototype vs `__proto__`、原型链查找、toString 来源
3. ✅ Q3 new 的 4 步：造对象、接原型链、call 绑 this、返回对象
4. ✅ Q4 this 指向：4 种绑定优先级（new > 显式 > 隐式 > 默认）、箭头函数
5. ✅ Q5 call/apply/bind：传参方式、执行时机、返回值
6. ✅ Q6 事件循环：宏任务/微任务队列、执行顺序、async/await
7. ⏳ Q7 Promise 手写：状态机、异步 resolve、回调数组、微任务包装（70%完成）

**关键收获**：
- 这 7 块是环环相扣的：new 用到原型链和 call，call 属于 this 显式绑定，事件循环解释了 Promise.then 为什么是微任务，Promise 手写用到状态机和事件循环。不是孤立知识点。
- 同一个地基（JS 底层）撑着 Vue 的 ref、React 的 useState、防抖节流。

**关键突破**：
- 从"闭包说反了"到能讲清 6 个场景（setTimeout、事件监听、防抖、ref、useState、箭头函数）
- 纠正了"this 向上找"的错误理解（原型链才向上找，this 看调用方式）
- 事件循环两道题（1432、164235）全对，理解"每个宏任务后清空微任务"

**学习方法验证**：
- "看笔记觉得会 → 合上嘴讲露出缺口"的方法有效
- 两次总结暴露了 new 四步、原型链作用、this 优先级的盲区
- 追问质量高（"call 为什么带参数"、"ref 的 get/set 是 class 自带的吗"）

**过程中的高质量提问**（说明真在动脑）：
- debounce 里 `fn.apply(this, args)` 的 args 是什么
- Vue3 ref 到底长什么样、get/set 是不是 class 自带
- `this.handleClick.bind(this)` 是什么意思
- 为什么 `onFulfilledCallbacks` 要用数组而不是单个变量

**习惯性偏差**（反复出现，需注意）：
