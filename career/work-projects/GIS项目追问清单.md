# GIS项目追问清单

更新时间：2026-06-11

## 使用方式

面向面试追问，不是纯理论问答。回答原则：先说结论 → 再说原因 → 最后说边界和演进。

## 一、项目背景与定位

### 1. 地质灾害GIS可视化项目是做什么的？

**答题要点**：
- 面向省/市/县三级用户的地质灾害综合监测驾驶舱
- 实时展示滑坡、泥石流、崩塌等地质灾害点的监测数据
- 支持预警调度、舆情管理、应急指挥
- 用户主要是自然资源局、应急管理局

### 2. 3000万规模具体包含什么？

**答题要点**：
- 这是整个项目的合同金额，包含前后端开发、硬件设备、现场实施
- 前端这块没有单独拆分预算，我作为前端核心开发负责全链路前端工作
- 涉及甘肃、云南、广西、青海等多省，每省的数据规模和监测点数量不同
- 甘肃省约8000个监测点，是规模最大的一个

### 3. 你的角色是什么？团队规模？

**答题要点**：
- GIS可视化：前端核心开发，负责驾驶舱、管理后台、移动端
- 搬迁项目：前端负责人，带2个前端
- 团队总规模：前端3-4人、后端4-5人、测试2人、产品1人、项目经理1人

## 二、技术架构与数据流

### 4. 监测数据从哪来？实时还是定时？

**答题要点**：
- 数据来源：现场监测设备（水位传感器、降雨量计、位移探测器、倾角仪）
- 数据上报：设备通过4G/NB-IoT上报到云端服务器，5分钟/次
- 前端获取：通过WebSocket实时推送 + 定时轮询（轮询作为降级方案）
- 历史数据：存储在后端数据库，前端按时间范围查询

### 5. 四个维度（图表/二维/三维/工作指挥）的技术栈分别是什么？

**答题要点**：
- **图表**：ECharts，展示监测点的指标趋势（水位变化、降雨量累计）
- **二维地图**：OpenLayers，展示灾害点和监测设备的地理分布
- **三维地图**：集成的三维引擎（类似Cesium），加载隐患点三维模型、设备实景定位
- **工作指挥**：Vue2表单 + 列表，预警调度、舆情管理、应急指令下发

### 6. 监测设备与隐患点/监测点的关联关系怎么建模？

**答题要点**：
- **监测点**：地理位置标注，一个监测点可能有多个隐患点
- **隐患点**：具体的滑坡体、泥石流沟，一个隐患点关联多个监测设备
- **监测设备**：水位计、雨量计、位移计等，一个设备只属于一个隐患点
- **前端建模**：表单驱动的关联关系录入，支持设备、隐患点、监测点的三级联动下拉

### 7. 图表和地图怎么做双向联动？

**答题要点**：
- **地图 → 图表**：点击地图上的监测点，右侧图表自动加载该点的历史趋势
- **图表 → 地图**：图表中选择某个时间点，地图上对应监测点高亮并展示当时状态
- **实现**：全局状态管理（Vuex），地图和图表组件监听同一个 `selectedPointId`
- **性能优化**：图表数据懒加载，只有点击时才请求，避免一次性加载所有监测点数据

## 三、性能优化

### 8. 首页加载提升50%，原来多少？现在多少？怎么测的？

**答题要点**：
- **优化前**：首页完全加载约7-8秒（包括地图瓦片、监测点数据、图表初始化）
- **优化后**：约3.5-4秒
- **提升约50%**：时间从7s降到3.5s，减少约50%
- **测试方法**：Chrome DevTools Performance面板，取10次加载的平均值，统计 `DOMContentLoaded` 到所有资源加载完成的时间

### 9. 首屏从3.5s优化至1.8s，具体做了什么？

**答题要点**：
- **Vite替换webpack**：开发环境冷启动从约30s降到3s，生产构建也快了很多
- **gzip压缩**：Nginx开启gzip，JS/CSS文件体积减少约70%
- **代码分割**：三维地图模块按需加载，不在首屏必须加载的内容
- **图片懒加载**：监测点图标、设备照片用懒加载
- **CDN**：地图瓦片、ECharts库走CDN，不打包到项目中

### 10. 分级加载的具体策略是什么？

**答题要点**：
- **省级视图**：只显示重点监测点（预警状态的、近期有异常的），约200-300个
- **市级视图**：点击某个市，加载该市所有监测点（约1000-2000个）
- **县级视图**：点击某个县，加载该县详细数据（包括历史趋势、设备列表）
- **实现**：地图缩放级别监听，根据zoom level和行政区划边界过滤数据

### 11. 显示时序控制怎么实现？

**答题要点**：
- **问题**：10000个监测点一次性渲染，浏览器主线程阻塞，页面卡死
- **方案**：用 `requestAnimationFrame` 分批渲染，每帧渲染100个点
- **代码思路**：把监测点数组分成多个批次，每次RAF回调渲染一批，直到全部渲染完成
- **用户体验**：点逐渐出现，不会一次性卡住，整体加载时间反而更短

### 12. 十万级监测数据是怎么处理的？

**答题要点**：
- **不是10万个点同时显示**：是历史数据总量，前端按需加载
- **地图上最多同时显示约5000个点**：通过分级加载控制
- **图表数据降采样**：一年的分钟级数据（50万+条），前端只展示关键点（峰值、谷值、突变点）
- **虚拟滚动**：设备列表用虚拟滚动，只渲染可视区域的DOM

### 13. 三维地图用的什么库？为什么不用Cesium？

**答题要点**：
- 用的是集成商提供的三维引擎，基于WebGL封装
- **为什么不用Cesium**：项目启动时（2022年）Cesium学习成本高、团队不熟悉
- 集成商的方案有现成模型库和工具链，可以快速交付
- **限制**：定制能力不如Cesium，但满足当前业务需求

## 四、搬迁项目

### 14. 搬迁项目的个人信息加密方案具体是什么？

**答题要点**：
- **前端展示加密**：身份证号中间位用星号替换（`123***890`），只在必要时显示完整信息
- **传输加密**：HTTPS + 请求体加密（AES-256对称加密）
- **密钥管理**：AES密钥用RSA非对称加密传输，前端用后端公钥加密AES密钥，后端用私钥解密
- **后端存储**：数据库字段加密存储，查询时解密后脱敏返回前端

### 15. 为什么不只用HTTPS，还要加一层请求体加密？

**答题要点**：
- **合规要求**：涉及个人敏感信息，必须端到端加密
- **HTTPS只保护传输层**：中间代理、CDN、网关可能看到明文
- **请求体加密**：即使HTTPS被中间人攻击，请求体仍是密文
- **实现成本**：前端用crypto-js，后端用Java Cipher，性能影响可接受

### 16. 搬迁项目前端负责人，团队几个人？周期多久？

**答题要点**：
- 团队：我 + 2个前端（一个负责PC端，一个负责移动端）
- 周期：约6个月（需求 → 开发 → 测试 → 上线 → 现场培训）
- 我的职责：方案设计、技术选型、代码审查、进度把控、现场交付

## 五、技术迁移与现场交付

### 17. Vue2到Vue3迁移遇到的最大问题是什么？

**答题要点**：
- **响应式API变化**：Vue2的 `this.$set` / `this.$delete` 在Vue3中废弃，改用 `ref` / `reactive`
- **生命周期钩子重命名**：`beforeDestroy` → `beforeUnmount`，需要全局替换
- **Vuex到Pinia**：状态管理迁移，Pinia没有mutations，只有actions
- **第三方库兼容**：部分Vue2插件没有Vue3版本，需要寻找替代方案或自己封装

### 18. .NET到Java后端迁移，前端需要改什么？

**答题要点**：
- **接口字段命名**：.NET用PascalCase（`UserName`），Java用camelCase（`userName`）
- **日期格式**：.NET返回 `yyyy-MM-dd HH:mm:ss`，Java可能返回时间戳，需要统一处理
- **错误码结构**：.NET和Java的错误响应格式不同，前端封装统一的错误处理
- **分页参数**：.NET用 `pageIndex` / `pageSize`，Java用 `page` / `size`，需要适配

### 19. 内网、麒麟、国密、UKey等信创环境适配是什么意思？

**答题要点**：
- **内网**：无外网访问，CDN资源本地化部署，npm私服
- **麒麟**：国产操作系统，浏览器内核可能是定制版Chromium，CSS兼容问题
- **国密**：HTTPS用国密算法（SM2/SM3/SM4），前端crypto库需要支持国密
- **UKey**：USB硬件密钥登录，前端需要调用UKey驱动的JS接口完成认证

### 20. 现场交付和客户培训具体做什么？

**答题要点**：
- **现场交付**：带着笔记本到客户现场，部署系统、数据初始化、功能演示
- **客户培训**：给自然资源局工作人员培训系统操作（录入监测点、查看预警、导出报表）
- **问题排查**：现场可能遇到网络不通、浏览器版本太低、数据格式不对，需要快速定位解决
- **经验**：提前准备培训PPT、操作手册、常见问题FAQ，带上备用方案（离线部署包、浏览器安装包）

## 六、项目成果与反思

### 21. GIS项目上线后的效果如何？

**答题要点**：
- 已在甘肃、云南、广西、青海等多省上线
- 用户反馈：地图加载速度快、数据展示直观、预警及时
- **实际案例**：甘肃某县发生泥石流灾害，系统提前2小时预警，及时疏散群众
- **遗留问题**：部分老旧浏览器（IE11）兼容性问题，三维地图在低配电脑上仍然卡顿

### 22. 如果让你重新做这个项目，会有什么调整？

**答题要点**：
- **技术栈**：一开始就用Vue3 + Vite，不用Vue2 + webpack
- **三维地图**：优先考虑Cesium，虽然学习成本高，但长期可维护性更好
- **数据缓存**：增加前端IndexedDB缓存层，离线也能查看历史数据
- **监控体系**：接入前端性能监控（Sentry / 阿里云ARMS），及时发现线上问题

### 23. 这个项目你最大的收获是什么？

**答题要点**：
- **性能优化能力**：从问题定位、方案设计到落地验证的完整经验
- **复杂业务理解**：地质灾害监测是专业领域，学会和领域专家沟通，理解业务语言
- **现场交付能力**：不只是写代码，还要能部署、培训、解决现场问题
- **团队协作**：作为前端负责人，学会任务拆解、进度把控、风险管理

### 24. GIS项目和讯飞项目相比，哪个更有挑战？

**答题要点**：
- **GIS项目挑战**：性能优化、数据可视化、现场交付

- **个人偏好**：讯飞项目更接近我现在的全栈AI方向，GIS项目偏传统前端可视化
