# 讯飞澳门项目追问清单

更新时间：2026-06-11

## 使用方式

面向面试追问，不是纯理论问答。回答原则：先说结论 → 再说原因 → 最后说边界和演进。

## 一、项目背景与定位

### 1. 智学网是做什么的？澳门项目的业务背景是什么？

**答题要点**：
- 智学网是科大讯飞旗下的智慧教育平台，在内地服务2500+学校
- 澳门项目是港澳市场拓展，需要支持澳门教育体系（繁体中文、英文、葡语）
- 核心是把试卷试题底层库系统做国际化和澳门业务规则适配
- 不影响大陆原流程是基本约束

### 2. 你的角色是什么？团队规模？

**答题要点**：
- 前端负责人，原前端骨干离职后接手
- 项目组约60人（前后端、测试、产品），前端这块我统筹5个系统
- 我负责方案设计、代码审查、业务验证和上线把关
- 具体编码有部分是我自己写，部分借助AI工具生成后我review

### 3. 为什么叫"遗留系统"？技术债有多重？

**答题要点**：
- 这几个系统是2018-2020年陆续建设的，Vue2 + webpack，还有一个Angular 4模块
- 代码风格不统一，组件重复开发，缺少统一规范
- 子项目之间有互相依赖，Element UI版本不一致
- 我接手时的第一件事是梳理依赖关系，制定隔离和兼容方案

## 二、i18n 双语言体系

### 4. 什么是"工作室语言"和"页面语言"？为什么要分开？

**答题要点**：
- **工作室语言**：资源加工区的业务数据语言，跟当前工作室绑定（简/繁/英/葡）
- **页面语言**：导航、菜单、按钮等界面元素语言，跟用户偏好绑定
- **为什么分开**：用户可能在简体界面下编辑繁体试题，两者必须独立决策
- 典型场景：大陆用户帮澳门加工繁体资源，界面用简体但业务数据用繁体

### 5. resolveBizLocale() 的判断逻辑是什么？

**答题要点**：
- 按**路由级**判断当前页面属于哪个区域
- 资源加工区（题目编辑、解析标注、相似题对比）：读取工作室语言
- 系统管理区（用户管理、权限配置）：读取用户偏好语言
- 前端在请求层注入 `X-Studio-Locale` 和 `X-User-Locale` 请求头，后端也按同样规则返回对应语言数据

### 6. 8个业务模块是哪8个？为什么这样划分？

**答题要点**：
- 题库管理、资源管理、众包加工、试题编辑、解析标注、知识点管理、权限管理、系统设置
- 按**业务功能域**划分，不按技术层划分
- 每个模块的语言文件独立，修改互不影响
- webpack用require.context按模块目录自动加载，不需要手动import

### 7. 为什么要拆成32个JSON？不会增加维护成本吗？

**答题要点**：
- **解决多人协作冲突**：原来一个大JSON，多人同时改必然冲突
- 32个 = 4种语言 × 8个模块，每人改自己负责的模块文件
- Git提交时只改动自己的文件，merge冲突大幅减少
- 维护成本：通过i18n-check卡口脚本自动检查，不需要人工逐个文件对比

### 8. i18n-check 的基线增量策略具体怎么实现？

**答题要点**：
- **首次运行**：扫描所有语言文件，记录当前所有问题（路径错位key、漏翻）到baseline.json
- **后续提交**：只拦截新增问题，存量问题标记为BASELINE_ISSUE不拦截
- **基线修复**：每修复一批存量问题，重新生成baseline，逐步归零
- **实现**：用Claude Code生成初版脚本，我定义拦截规则（key路径规范、4语言完整性），AI生成AST遍历和diff逻辑

### 9. 为什么不用成熟的i18n检查工具？

**答题要点**：
- 成熟工具（如i18next-scanner）主要检查代码中是否使用了不存在的key
- 我们的问题是**语言文件内部一致性**：4种语言key必须对齐、不能漏翻
- 我们的项目有自己的key命名规范（模块.页面.组件.字段），通用工具无法定制
- 自研脚本可以精确匹配项目规范，误报率低

### 10. husky pre-commit 会不会拖慢提交速度？

**答题要点**：
- 会慢一点（约3-5秒），但可以接受
- 只检查本次提交涉及的语言文件，不是全量扫描
- 相比人工自检4种语言，这点时间完全值得
- 如果确实需要紧急提交，可以 `git commit --no-verify` 跳过（但不推荐）

## 三、富文本公式组件化

### 11. 为什么富文本公式有四条渲染链路？

**答题要点**：
- **Wiris图片公式**：历史数据，已经是图片格式，直接展示
- **LaTeX**：数学公式标准格式，需要MathJax渲染
- **MathJax**：LaTeX的渲染引擎，把 `$$x^2$$` 转成可视化公式
- **图片兜底**：上述都失败时，降级显示为普通图片或占位符
- **优先级**：Wiris > LaTeX+MathJax > 图片兜底

### 12. 原子组件、通用组件、业务组件怎么划分？举个例子？

**答题要点**：
- **原子组件**：`<FormulaRenderer>` 只负责单个公式渲染，输入LaTeX输出DOM
- **通用组件**：`<FormulaEditor>` 带工具栏（插入公式、预览、切换模式）
- **业务组件**：`<QuestionEditor>` / `<AnswerEditor>` 封装了题目/解析场景的特定逻辑
- **复用链条**：题目编辑、解析标注、相似题对比都复用 `<FormulaEditor>`，各自封装业务层

### 13. 为什么不直接用一个大组件搞定所有场景？

**答题要点**：
- **职责不清**：一个组件既管渲染、又管编辑、又管业务逻辑，维护困难
- **复用困难**：新场景需要部分功能时，只能复制粘贴改
- **测试困难**：原子组件可以独立测试渲染逻辑，业务组件测试业务逻辑
- **分层后好处**：只需要渲染的场景用原子组件，需要编辑的场景用通用组件，业务定制用业务组件

### 14. Wiris 和 LaTeX 有什么区别？

**答题要点**：
- **Wiris**：商业公式编辑器，生成的是图片格式（PNG/SVG），历史数据很多用这个
- **LaTeX**：开源的数学公式排版语言，纯文本格式（如 `x^2 + y^2 = z^2`）
- **区别**：Wiris是所见即所得编辑器，LaTeX是标记语言需要渲染引擎
- **当前策略**：优先展示Wiris图片（加载快），LaTeX用MathJax实时渲染

### 15. 跨版本兼容怎么做的？

**答题要点**：
- **问题**：rmp用Element UI 2.13，rpp-web用2.15，组件接口有breaking change
- **方案**：共享组件内部做版本检测，按不同版本调用不同API
- **示例**：`el-select` 的 `change` 事件在2.13和2.15返回值结构不同，组件内部统一成一致格式再向上透传
- **长期方案**：推动各系统统一升级到同一个Element UI版本（但当前业务节奏不允许）

## 四、系统级风险与架构决策

### 16. "子项目互相依赖"具体是什么依赖？怎么隔离的？

**答题要点**：
- **依赖问题**：rmp直接import rpp-web的工具函数，但rpp-web不是发布的npm包
- **风险**：rpp-web改了工具函数接口，rmp不知道，上线后崩溃
- **隔离方案**：把共享代码抽到独立npm包 `@xf-tkms/shared-utils`，版本化管理
- **迁移策略**：不一次性全抽，先抽稳定的工具函数，逐步迁移

### 17. 你作为前端负责人，怎么做代码审查？标准是什么？

**答题要点**：
- **审查重点**：业务逻辑正确性 > 代码规范 > 性能优化
- **业务逻辑**：语言切换是否正确、数据隔离是否到位、边界场景处理
- **代码规范**：变量命名、函数拆分、注释完整性
- **性能优化**：循环中的不必要请求、大列表未做虚拟滚动
- **工具**：GitLab MR + Code Review Checklist，关键模块我会本地拉代码跑一遍

### 18. 前任为什么离职？你接手时最大的挑战是什么？

**答题要点**：
- 前任个人原因离职（职业规划调整），和项目无关
- **最大挑战**：没有完整交接文档，5个系统的依赖关系、技术债、遗留问题都要自己梳理
- **应对**：第一周通读代码、梳理依赖关系图、列出技术债清单
- **团队稳定**：和其他前端同学多沟通，快速建立信任，明确分工

## 五、AI 辅助开发

### 19. 你具体怎么用 Claude Code 和 Cursor？

**答题要点**：
- **Claude Code**：用于需求拆解、方案设计、代码审阅
- **Cursor**：用于代码生成、重复性改造
- **典型流程**：我先写需求文档和接口设计，Claude Code生成方案建议，我确认后交给Cursor生成代码，我逐行review
- **生成率vs审查率**：简单重复代码（如批量加语言切换）AI生成80%+，核心业务逻辑我自己写或AI生成后大改

### 20. 你自己写了多少代码？AI 生成了多少？

**答题要点**：
- **核心架构代码**（resolveBizLocale、三层组件设计、i18n-check脚本）：我自己写或AI生成初版后我重写
- **重复性改造**（给每个页面加语言参数、批量替换API调用）：AI生成为主，我review和调整
- **比例**：核心代码约30%我写，AI辅助重复代码约70%，但所有代码都经过我review
- **关键**：方案决策、架构设计、业务验证100%我把关

### 21. 会不会被质疑"你到底会不会写代码"？

**答题要点**：
- **实力证明**：i18n双语言决策架构、三层组件设计、基线增量策略都是我设计的
- **代码审查能力**：我能准确指出AI生成代码的问题（业务逻辑错误、性能隐患、边界场景遗漏）
- **类比**：就像架构师用脚手架生成项目骨架，不会被质疑"不会搭项目"
- **AI定位**：AI是我的代码助手，不是我的替代品
