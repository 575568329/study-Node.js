# RAG项目追问清单

更新时间：2026-05-07

## 使用方式

这份清单面向面试追问，不是纯理论问答。

回答原则：

1. 先说结论
2. 再说原因
3. 最后说当前边界和后续演进

---

## 一、项目定位

### 1. 这个项目解决什么问题？

答题要点：

- 解决专业资料分散、检索效率低
- 用户不再手动翻文件
- 用自然语言提问，系统返回答案和来源

### 2. 这个项目的核心价值是什么？

答题要点：

- 检索增强问答，不是纯聊天机器人
- 把资料入库、检索、回答、追溯做成闭环
- 更适合专业领域知识使用场景

---

## 二、文档入库

### 3. 为什么上传后要先解析成纯文本？

答题要点：

- 统一后续切片和 embedding 输入
- 不同格式走同一条处理链路
- 方便检索和来源回溯

### 4. 当前支持哪些文档格式？怎么解析？

答题要点：

- `.txt` / `.md`：`file.text()`
- `.pdf`：`pdfjs-dist`
- `.docx`：`mammoth`
- `.xlsx`：`ExcelJS`

### 5. 为什么要做切片，而不是整篇向量化？

答题要点：

- 检索粒度更细
- 避免整篇语义被稀释
- 降低 token 成本
- 避免上下文窗口超限

### 6. 切片参数为什么这样设置？

答题要点：

- 当前 `chunkSize=1000`、`overlap=100`
- 兼顾单片段信息量和召回准确性
- overlap 用于降低跨片段信息断裂

---

## 三、检索与问答

### 7. 为什么不能直接把整份文档交给大模型？

答题要点：

- token 成本高
- 噪音多，容易偏题
- 文档一大就碰到上下文窗口限制
- RAG 是先检索、再生成

### 8. 当前项目问答链路怎么跑？

答题要点：

- 构造 `searchQuery`
- 确定知识库范围
- query embedding
- 相似度 / 混合检索
- topK 召回
- prompt 组装
- `glm-4-flash` 流式回答
- 返回 `sources`

### 9. 什么是单知识库模式？什么是全部知识库模式？

答题要点：

- 单知识库：范围小、噪音低、精度更高
- 全部知识库：覆盖更广，支持跨库查询
- 本质是精度和范围的平衡

### 10. 当前全部模式怎么做？未来怎么升级？

答题要点：

- 当前：跨所有知识库统一检索
- 问题：数据量大时噪音和资源消耗上升
- 升级：AI 路由先返回候选知识库及置信度，再缩小检索范围

### 11. 为什么要返回 Sources？

答题要点：

- 让答案可追溯
- 用户能回看原文
- 提高可信度
- 帮助区分检索层和生成层问题

### 12. 回答不准时你怎么排查？

答题要点：

- 先看 sources 是否相关
- 再看日志里的检索结果
- 召回错：检索层问题
- 召回对但回答偏：生成层 / prompt / 模型问题

## 四、存储与架构

### 13. 为什么向量存储层要抽象成 FileStore / ChromaStore？

答题要点：

- 解耦上层问答链路和底层存储
- 当前优先低成本演示
- 后续保留升级空间

### 14. 为什么当前默认使用 FileStore？

答题要点：

- 本地演示成本低
- 无额外依赖
- 适合个人项目和小规模数据

### 15. FileStore 的局限是什么？

答题要点：

- JSON 文件读写不适合高并发
- 可能写覆盖、锁竞争
- 不适合大规模向量检索

### 16. 后续存储怎么演进？

答题要点：

- 业务元数据：SQLite / PostgreSQL
- 向量存储：Chroma / pgvector
- 文件：对象存储或独立上传目录

---

## 五、图谱增强

### 17. 为什么图谱抽取异步执行？

答题要点：

- 图谱是增强链路
- 不阻塞上传和问答主流程
- 失败隔离

### 18. 当前图谱能力做到什么程度？

答题要点：

- 支持实体关系抽取和图谱可视化
- 支持搜索、节点详情、邻域扩展、收藏
- 还没有进入问答主链路

### 19. 为什么现在不能叫完整 GraphRAG？

答题要点：

- 图谱当前主要用于展示和浏览
- 问答还没依赖图谱增强检索
- 不能把增强展示写成核心检索能力

---

## 六、项目边界

### 20. 这个项目当前最大的不足是什么？

答题要点：

- 业务存储和向量存储仍是本地方案
- 全部模式还没有 AI 路由
- 图谱状态展示未闭环
- 没有权限隔离和生产级并发保障

### 21. 你为什么还敢把它写到简历里？

答题要点：

- 主体闭环已经完整
- 能跑、能演示、能讲清楚
- 简历表达会按“个人项目 / 演示级系统”边界来写，不夸大

### 22. 这个项目最大的技术亮点是什么？

答题要点：

- 把传统文档搜索升级为 RAG 检索增强问答
- 有完整入库、检索、流式回答、来源追溯闭环
- 不只是简单调用大模型接口
