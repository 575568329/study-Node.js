# 各项目亮点与面试表达总结

> 目标：从项目本身出发，总结每个项目可用于简历和面试的亮点。  
> 口径：不只看 `fjyu9` 的提交数量，而是结合项目结构、业务模块、代码实现和澳门国际化改造内容，提炼“为什么是亮点、值得学习什么、面试时体现哪类能力”。

## 1. 总体判断

这组项目的核心价值不是“写了很多页面”，而是围绕澳门市场，把原来面向大陆教育场景的一整套题库、资源管理、资源加工、众包加工、专题教材管理和遗留 Java Web 系统做业务规则扩展。

面试时最值得讲的主线是：

- 原系统不是为多语言设计的，需要在既有流程里增加澳门业务来源、资源语言、澳门题型、基本学力、澳门知识点等维度。
- 多语言不是简单替换文案，而是会影响题型、教材版本、册别、出版社、目录、知识点、基本学力、题目展示、导入导出、审核流程等业务数据。
- 改造不能影响大陆业务，需要通过参数隔离、组件复用、接口透传和回归验证控制风险。

这类项目在面试中体现的能力主要是：

- 复杂业务理解能力
- 遗留系统改造能力
- 跨页面数据链路设计能力
- 国际化和兼容性处理能力
- 富文本 / 题库内容处理能力
- 工程化和风险控制能力

## 2. rpp-web：资源加工平台 / 众包加工主链路

### 2.1 项目定位

`rpp-web` 是资源加工平台前端，业务范围包括工作室、任务管理、众包加工、划题、标注、审核、校对、纠错、同类题、相似题、导入、详情页、任务结果页、题目展示和题目对比等。

它是这组项目里最适合在面试中重点讲的项目，因为它覆盖了完整的资源加工业务链路，且澳门多语言改造贯穿了多个页面和公共组件。

### 2.2 亮点一：`macaoParams` 多语言参数链路贯通

亮点是什么：

- 从任务、资源包、工作室等入口解析澳门业务来源和资源语言。
- 将 `macaoParams` 传递到加工页、子流程、题目编辑器、题目展示组件、题目对比组件、API 层。
- 支持 `isMacao`、`languageLabel`、`languageLabelMacao`、`areaSectionCode` 等参数在多页面复用。

为什么是亮点：

- 众包加工不是单页面，而是一个长链路。标注、审核、校对、纠错、相似题、详情页和结果页都要知道当前题目是不是澳门题目、用哪种资源语言、用哪套知识点标签。
- 如果每个页面都自己判断，会出现某个页面题型对了、另一个页面解析文案不对、对比页又没有基本学力的情况。
- 把澳门上下文抽象成统一参数，本质是在做“业务上下文建模”，比单纯写页面逻辑更有技术含量。

值得学习什么：

- 跨页面复杂业务不要散落判断，应抽象稳定的业务上下文对象。
- 参数命名要明确区分内部语言码、locale、知识点标签、区域编码。
- 业务主判断和展示语言判断要分离，例如主判断按 `secondBizSource`，资源语言只决定数据维度。

面试属于哪部分比较厉害：

- 属于“复杂业务建模 + 前端架构设计”能力。
- 可以作为你项目里最强的技术亮点之一来讲。
- 面试官如果问“你做过什么不是简单 CRUD 的东西”，这个点最适合展开。

推荐表达：

> 我把澳门业务来源、资源语言、知识点标签和区域编码抽象成 `macaoParams`，从任务入口统一透传到标注、审核、校对、纠错、题目展示和对比组件，避免每个页面重复判断，降低了多语言链路漏传风险。

### 2.3 亮点二：众包加工全流程多语言适配

亮点是什么：

- 覆盖划题、标注、审核、校对、纠错、同类题、相似题、解析对比、详情页和结果页。
- 根据澳门业务来源和资源语言加载题型、知识点、目录、试题来源和基本学力。
- 非澳门业务保持原逻辑，避免回归。

为什么是亮点：

- 众包加工流程是教育资源平台的核心生产流程，业务链路长，页面间依赖多。
- 每个环节数据来源不完全一致，例如标注页、审核页、校对页控制字段不一样。
- 多语言字段不只是展示，还会影响搜索、筛选、提交、导出和回显。

值得学习什么：

- 做复杂流程改造时，要先画清楚链路：入口数据来自哪里、传到哪些组件、保存时用哪些字段、详情页如何回显。
- 不能只测当前页面，还要测“列表进入加工页、加工页进入详情、结果页再对比”的跨页面链路。
- 对业务系统来说，“不影响老业务”本身就是技术目标。

面试属于哪部分比较厉害：

- 属于“复杂业务流程改造 + 风险控制”。
- 适合回答“你怎么处理多模块联动”“如何保证改造不影响老流程”。

推荐表达：

> 我不是只做某个表单的语言字段，而是把澳门资源语言贯通到众包加工全流程，覆盖任务管理、划题、标注、审核、校对、纠错、题目展示和结果详情，并把非澳门业务作为固定回归项。

### 2.4 亮点三：基本学力第一/第二语言展示逻辑

亮点是什么：

- 基本学力展示依赖任务工作项、题目编辑器白名单、知识点组件、第一/第二语言字段等多个条件。
- 不同页面使用的控制字段不同，例如 `taskItems`、`workItemSet`、`questionRule.whitelist`。
- 需要把 `BasicAcademicAbility` 和 `BasicAcademicAbilitySecond` 同时纳入编辑器和展示组件逻辑。

为什么是亮点：

- 这是典型的“业务字段来源不统一”问题，不是前端展示判断那么简单。
- 如果只看接口返回，很容易误判“接口有 191/193 就应该显示”，但实际组件还受白名单和知识点显示条件控制。
- 能讲清楚这个点，说明你理解了业务数据、组件权限和页面展示之间的关系。

值得学习什么：

- 排查复杂展示问题时，不要只看一个接口，要找完整控制链路。
- 白名单、工作项、组件显隐、数据候选源要分层分析。
- 业务系统中“字段返回了但页面不显示”通常是多条件共同控制。

面试属于哪部分比较厉害：

- 属于“复杂问题排查 + 业务规则理解”。
- 适合回答“你遇到过比较难排查的 bug 吗”。

推荐表达：

> 基本学力不展示不是一个简单 v-if 问题，我排查了任务工作项、资源包 workItem、审核白名单和题目编辑器白名单之间的关系，最后按不同流程补齐第一/第二语言展示条件。

### 2.5 亮点四：导入、详情、结果页的语言回显一致性

亮点是什么：

- Word 导入、ID 导入、压缩包导入需要显示澳门试题类型和资源语言。
- 详情页和结果页需要按同一语言回显题目字段、基本学力和解析对比。
- 需要处理 `questionLanguage`、`pkgVo.languageCode`、默认 `zh_CN` 等兜底。

为什么是亮点：

- 很多项目只关注提交页，忽略详情页和结果页回显，最终会出现“提交是葡文，详情显示中文”的问题。
- 导入类场景通常涉及批量数据，错误会放大。
- 结果页是验收和审核入口，语言错了会直接影响业务判断。

值得学习什么：

- 表单提交、列表查询、详情回显、结果展示必须统一看。
- 多语言字段要有明确优先级和兜底策略。
- 批量导入场景要特别注意参数一致性。

面试属于哪部分比较厉害：

- 属于“数据一致性 + 端到端链路思维”。
- 适合回答“你如何保证功能闭环”。

## 3. rmp：题库资源管理 / 知识体系 / 富文本公式

### 3.1 项目定位

`rmp` 是资源管理和题库底层管理类系统，包含图书、教辅、知识点、澳门知识体系、基本学力、标签、学制、资源导出、知识点映射等模块。

它适合在面试中讲“题库底层数据复杂度”和“富文本公式兼容”。

### 3.2 亮点一：澳门知识体系与多套知识点映射

亮点是什么：

- 项目包含澳门知识体系管理。
- 支持澳门知识点与图书目录、新课标知识点、基本学力之间的关联和取消关联。
- 支持按目录、按体系、按基本学力导出映射数据。

为什么是亮点：

- 题库系统的难点在于知识结构复杂，不是简单的树增删改查。
- 澳门知识体系、图书目录、新课标知识点、基本学力是不同领域模型，彼此之间存在映射关系。
- 映射错了会影响后续题目加工、推荐、审核和资源使用。

值得学习什么：

- 教育题库系统的核心不是题目本身，而是题目背后的知识体系、教材目录和能力维度。
- 多知识体系映射要关注双向关系、导出校验、关联取消、空数据兜底。
- 树结构管理要考虑层级、禁用节点、超长标题、导出和批量操作。

面试属于哪部分比较厉害：

- 属于“复杂业务数据建模 + 树结构管理”。
- 面试时能体现你不只是做后台页面，而是理解题库底层数据结构。

推荐表达：

> 在 rmp 中，澳门知识体系不是单独维护一棵树，而是要和图书目录、新课标知识点、基本学力建立映射，这类功能考验的是对题库底层数据结构的理解。

### 3.3 亮点二：富文本公式兼容方案

亮点是什么：

- 处理 CKEditor / Wiris / LaTeX / MathJax / 图片公式多种形态。
- 将可识别的 Wiris 图片公式转换为 LaTeX 行内公式，用 MathJax 渲染。
- 对特殊 LaTeX、解析失败、Math input error 等情况保留原始图片兜底。
- 增加 MathJax 渲染重试和重复渲染保护。

为什么是亮点：

- 教育题目里的公式是核心内容，不能丢失。
- 历史数据形态复杂，不可能一次性清洗成理想格式。
- 正确策略不是“全部强转 MathJax”，而是“能渲染则渲染，不能渲染保留图片”。
- 这体现了防御式编程和兼容历史数据的能力。

值得学习什么：

- 富文本处理要优先保证内容正确性，而不是追求统一渲染形式。
- DOM 渲染要考虑时机，MathJax 这类异步渲染需要重试和并发保护。
- 对历史数据要做分级兜底：正常数据、特殊数据、异常数据分别处理。

面试属于哪部分比较厉害：

- 属于“富文本 / 复杂内容渲染 / 兼容性工程”。
- 这是前端面试里很容易讲出深度的点，比普通表单强很多。

推荐表达：

> 我处理过题库富文本公式兼容问题，把 Wiris 图片公式按 `data-latex` 转为 MathJax 可渲染格式，对异常公式保留图片兜底，并加了渲染重试和重复渲染保护，保证公式内容不丢失。

### 3.4 亮点三：知识点树组件和老系统集成

亮点是什么：

- 项目中既有 Element Tree，也有 zTree / giant-tree 这类老组件。
- 知识点管理涉及节点新增、编辑、删除、层级控制、超长标题、禁用状态、说明弹窗、导出等。
- 需要处理 jQuery 插件和 Vue 组件生命周期的兼容。

为什么是亮点：

- 老系统经常不是纯 Vue，而是 Vue + jQuery 插件 + 全局脚本混合。
- 这类项目的难点不是 API 调通，而是让老插件在现代组件体系里稳定工作。
- zTree 这种插件需要关注初始化、销毁、重复渲染、全局依赖和事件回调。

值得学习什么：

- 遗留系统改造不能盲目推翻重写，要学会包一层组件适配。
- 对第三方老插件要管理生命周期，避免重复初始化和内存泄漏。
- 树结构场景要重视性能、层级、节点状态和交互细节。

面试属于哪部分比较厉害：

- 属于“遗留系统治理 + 第三方插件封装”。
- 适合回答“你怎么处理老项目中的技术债”。

## 4. tkms-fresh-web：专题 / 教材 / 资源管理

### 4.1 项目定位

`tkms-fresh-web` 更偏资源专题、教材、精品专题和屏蔽管理。澳门改造集中在 `macaoAlbum`、专题发布语言、发布业务、教材版本、教材册别、资源语言和 `isMacao` 数据隔离。

### 4.2 亮点一：澳门专题与大陆专题数据隔离

亮点是什么：

- 澳门专题页面和普通专题页面共用部分组件。
- 通过 `isMacao` 控制专题类型、列表、排序、新增编辑等接口参数。
- 注释中明确“仅澳门专题管理场景追加 isMacao，避免影响普通专题类型查询”。

为什么是亮点：

- 业务复用组件时，最大风险是新业务影响老业务。
- 澳门专题和大陆专题看起来类似，但查询范围、发布语言、发布业务和教材数据不同。
- 显式传 `isMacao` 是一种低风险隔离策略。

值得学习什么：

- 复用组件时要把业务差异做成显式参数，而不是在组件内部隐式猜测。
- 新业务接入老系统时，接口参数应尽量“只在新业务场景追加”，避免改变默认行为。
- 注释要解释为什么要隔离，而不是只解释代码做了什么。

面试属于哪部分比较厉害：

- 属于“组件复用 + 业务隔离设计”。
- 适合回答“如何在老系统中接入新业务而不影响旧业务”。

推荐表达：

> 澳门专题和普通专题共用部分组件，我通过 `isMacao` 显式区分业务场景，只在澳门入口追加参数，避免普通专题查询和编辑逻辑被污染。

### 4.3 亮点二：发布语言切换导致的数据清理

亮点是什么：

- 澳门专题新增/编辑包含发布语言。
- 切换发布语言后，教材目录、子栏目、资源数据需要重置。
- 编辑专题时，部分子栏目是后端实时数据，需要先调用删除接口清空。

为什么是亮点：

- 发布语言是专题的核心数据维度，一旦切换，原来选的教材、目录、资源可能全部不合法。
- 这里不是简单清空前端表单，还要处理已经落库的子栏目数据。
- 能正确处理说明你理解“编辑态”和“新增态”的差异。

值得学习什么：

- 表单联动中，关键维度变化时要识别哪些数据必须清空。
- 编辑态如果存在后端实时数据，不能只改前端状态，要同步后端。
- 重要操作需要确认提示，避免用户误删配置。

面试属于哪部分比较厉害：

- 属于“复杂表单状态管理 + 数据一致性”。
- 适合回答“你做过复杂表单联动吗”。

### 4.4 亮点三：教材版本 / 册别屏蔽管理

亮点是什么：

- 支持按资源语言、学段、学科、教材版本筛选教材。
- 管理教材版本和教材册别在不同场景下的屏蔽状态。
- 支持批量屏蔽、授权场景判断、已屏蔽/未屏蔽过滤。
- 澳门场景下对屏蔽范围做特殊判断。

为什么是亮点：

- 这不是普通列表，而是带有业务规则的状态管理。
- 教材版本和册别有父子关系，版本屏蔽和册别屏蔽需要保持一致。
- 授权、屏蔽、场景、资源语言多个条件共同决定最终可操作数据。

值得学习什么：

- 父子数据状态联动要定义清楚一致性规则。
- 管理类页面要关注“可操作”和“不可操作”的原因展示。
- 筛选条件变化时要处理已选数据是否仍然有效。

面试属于哪部分比较厉害：

- 属于“复杂后台管理业务 + 状态一致性”。
- 适合回答“你做过复杂后台管理页面吗”。

## 5. gxh-erm：Java Web 遗留服务 / 教辅与目录基础数据

### 5.1 项目定位

`gxh-erm` 是 Java Web 遗留系统，技术栈包含 Spring、Dubbo、Maven、Struts/Servlet 风格 action、服务层和工具类。澳门改造主要涉及教辅、目录信息、基础属性下拉、语言化名称和部分区域树。

### 5.2 亮点一：基础下拉数据按语言返回

亮点是什么：

- `BasicPropertiesUtil` 支持按 `languageCode` 返回学科、册别、版本、出版社等基础属性名称。
- 如果指定语言有翻译，则返回语言描述；如果没有，则回退默认名称。
- 前端新增/编辑时可以按资源语言加载下拉数据。

为什么是亮点：

- 这是多语言业务的基础设施，不是单页面功能。
- 学科、版本、册别、出版社会被很多页面复用。
- 后端提供语言化基础数据后，前端不需要在各页面硬编码翻译。

值得学习什么：

- 多语言动态业务数据应尽量由数据源或后端返回，而不是前端写死映射。
- 后端适配要保留默认值兜底，避免缺失翻译导致页面空白。
- 基础数据服务一旦做好，可以支撑多个前端页面。

面试属于哪部分比较厉害：

- 属于“前后端协同 + 基础数据国际化”。
- 对前端候选人来说，这是加分项：说明你不只会改页面，也能理解服务端数据来源。

推荐表达：

> 在 Java 遗留系统中，我补充了基础属性按语言返回的能力，学科、版本、册别、出版社等下拉数据优先取指定语言描述，缺失时回退默认名称，支撑前端资源语言切换。

### 5.3 亮点二：教辅目录和区域树的语言化适配

亮点是什么：

- 教辅列表、新增编辑、目录信息弹窗等都需要资源语言。
- 区域树支持按 `languageCode` 获取语言化数据。
- 编辑态切换资源语言时，需要处理年份、加工方、目录等字段是否清空。

为什么是亮点：

- 教辅和目录是题库资源的基础维度，影响后续资源加工、题目导入和目录筛选。
- 语言切换后，旧目录数据可能不再属于当前语言。
- 编辑态数据回显比新增态更复杂，不能简单重置所有字段。

值得学习什么：

- 复杂业务表单要区分“语言强相关字段”和“语言弱相关字段”。
- 编辑回显时要避免过度清空，也要避免保留非法旧数据。
- 前后端要约定哪些字段由语言决定。

面试属于哪部分比较厉害：

- 属于“业务表单联动 + 后端数据适配”。

## 6. crowdsourced-new-web：Angular 众包遗留系统

### 6.1 项目定位

`crowdsourced-new-web` 是 Angular 4 + Java WAR 的新众包 Web 系统，包含任务结果、资源包详情、题目反馈、统计、错误处理、任务管理和公共题目展示组件。

它适合在面试中作为“多技术栈遗留系统适配”的补充项目，不建议作为主项目讲太多，除非面试官问 Angular 或老项目迁移。

### 6.2 亮点一：Angular 老项目中的多语言结果页适配

亮点是什么：

- `task-result` 中根据 `taskVo.questionLanguage`、`pkgVo.languageCode` 等字段归一化语言。
- 详情页只识别澳门当前四种语言，异常值回退 `zh_CN`。
- 语言传给结果组件、对比组件、纠错组件。

为什么是亮点：

- 这是在 Angular 老项目中做与 Vue 项目一致的澳门语言回显逻辑。
- 老项目类型系统、组件输入和服务封装方式与 Vue 完全不同。
- 能跨技术栈复用同一套业务规则，说明业务理解不是绑在某个框架上。

值得学习什么：

- 多语言逻辑要有框架无关的业务规则。
- 老 Angular 项目中要重视组件输入输出和 service 数据源。
- 异常语言值要做归一化和兜底。

面试属于哪部分比较厉害：

- 属于“跨技术栈适配 + 遗留系统维护”。
- 适合体现你不只会 Vue，也能处理 Angular 旧系统。

推荐表达：

> crowdsourced-new-web 是 Angular 4 老系统，我在结果页和对比组件中补充语言归一化和传参逻辑，让它和 Vue 资源加工平台保持一致的澳门多语言回显规则。

### 6.3 亮点二：众包统计和任务结果体系复杂

亮点是什么：

- 项目中存在标注、审核、二审、校对、校对审核、主改客、分题型工作量统计等模块。
- 任务结果页聚合基础题、结构题、相似题、卡片等多种结果组件。

为什么是亮点：

- 众包系统不仅是做题页面，还有任务分发、统计、计量、审核结果和反馈闭环。
- 这能帮助你理解资源加工平台背后的生产管理逻辑。

值得学习什么：

- B 端系统往往有“生产流程 + 质量控制 + 工作量统计”三条线。
- 结果页和统计页是业务闭环的重要部分，不是附属页面。

面试属于哪部分比较厉害：

- 属于“业务全局理解”。
- 可以作为补充说明你理解众包加工系统的上下游。

## 10. 最推荐的面试项目讲法

可以这样开场：

> 我最近做的比较完整的是讯飞智学网澳门市场国际化改造。这个项目不是单纯翻译页面，而是把原来面向大陆教育业务的题库和资源加工平台扩展到澳门市场。澳门场景新增了资源语言、澳门题型、基本学力第一/第二语言、澳门知识点等维度，这些维度会影响题目编辑、审核、校对、纠错、导入、详情、结果页和后台专题教材管理。  
>  
> 我主要做了三类事情：第一是把澳门业务来源和资源语言抽象成统一的 `macaoParams`，贯通众包加工全链路；第二是处理题库富文本公式和历史数据兼容，比如 Wiris、LaTeX、MathJax 和图片公式兜底；第三是在专题教材和 Java 遗留系统中补充资源语言和数据隔离，保证澳门业务上线不影响大陆原流程。

如果面试官追问“最难的点是什么”：

> 最难的是澳门参数链路。因为任务详情、资源包、工作室、题目编辑器、题目展示、对比组件和接口层都要用到语言信息，任何一个页面漏传都会表现为题型、知识点或基本学力不对。我没有在每个页面零散写判断，而是抽出 `macaoParams`，把是否澳门、资源语言、知识点标签、区域编码等信息统一向下传递，并把非澳门业务作为固定回归项。

如果面试官追问“有什么技术细节”：

> 技术细节可以讲公式兼容。历史题库里有 Wiris 图片公式、LaTeX、MathML 和普通图片。我做的策略是优先读取 `data-latex` 转成 MathJax 可渲染格式，如果遇到特殊公式或解析失败就保留原图，保证题目内容不丢失。同时 MathJax 渲染有 DOM 时机问题，所以加了 `$nextTick`、延迟重试和重复渲染保护。
