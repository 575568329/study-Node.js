## 5. 核心技术难点

### 5.1 多语言不是文案替换，而是业务数据维度切换

项目中的资源语言会影响题型、试题来源、学段学科、教材版本、册别、出版社、目录、基本学力、知识点等接口数据。页面切换资源语言后，不仅要替换展示文案，还要清空依赖字段、重新请求下拉数据、处理编辑回显和默认值，否则容易出现“页面显示澳门语言，但保存的是大陆数据”的问题。

简历表达：

- 设计资源语言联动机制，切换语言时重置依赖字段并重新加载版本、册别、出版社、题型、试题来源等业务数据，保证编辑回显和提交数据一致。

### 5.2 澳门和大陆流程共用，不能污染原业务

项目不是新建一套澳门系统，而是在原有大陆业务系统中增加澳门逻辑。很多页面和接口被大陆业务长期使用，因此澳门逻辑必须通过 `secondBizSource`、`isMacao`、`isMacaoStudio`、`languageCode` 等参数隔离，不能直接修改默认行为。

简历表达：

- 通过业务来源和资源语言参数隔离澳门与大陆数据链路，保证澳门功能上线的同时不影响原大陆业务流程。

### 5.3 众包加工链路长，参数容易断

众包流程涉及管理员列表、任务详情、加工页、标注、审核、校对、纠错、题目展示、解析对比、详情页等多个入口。澳门相关参数需要从任务和资源包入口一路传到题目编辑器、题目查看组件、对比组件和 API 层，任何一个环节漏传都会导致题型、知识点、基本学力展示异常。

简历表达：

- 梳理并贯通众包加工 `macaoParams` 传递链路，覆盖任务详情、加工子流程、题目编辑器、题目展示和解析对比组件，解决多页面澳门信息漏传问题。

### 5.4 基本学力显示依赖多个字段

基本学力不是单纯接口返回就能展示，它同时依赖任务工作项、题目编辑器白名单、知识点组件可见性、第一/第二语言字段等条件。不同流程中字段来源不一致，例如标注页、审核页、校对页的控制字段不同，需要分别梳理。

简历表达：

- 梳理基本学力第一/第二语言在标注、审核、校对、纠错流程中的展示条件，统一白名单和组件显示逻辑，修复部分页面基本学力不展示问题。

### 5.5 富文本和公式要兼容历史数据

题库内容中存在 CKEditor、Wiris、LaTeX、MathJax、图片公式等多种历史数据形态。理想情况下公式可以统一用 MathJax 渲染，但历史数据可能缺少合法 LaTeX、包含特殊公式或解析错误，因此必须保留图片兜底，优先保证题目内容不丢失。

简历表达：

- 优化富文本公式兼容方案，将可识别公式转换为 MathJax 渲染，对异常公式保留图片兜底，提升题目内容展示稳定性。

### 5.6 国际化布局要按文本类型治理

英文、葡文文本比中文更长，且存在长单词、无空格编码串、复合词等情况。项目中大量表格、弹窗、标签和固定宽度容器原本按中文长度设计，直接翻译会导致内容溢出。

简历表达：

- 按文本类型制定国际化布局策略，区分单行省略、自然换行、强制断词和多行截断，修复长英文/葡文导致的表格、弹窗和标签溢出问题。

## 6. STAR 案例

### 案例 1：资源语言联动和数据回显

- S：澳门业务要求不同资源语言下展示不同的学科、版本、册别、出版社、题型和试题来源。
- T：在不影响大陆业务的情况下，让新增、编辑、列表筛选和详情回显都能按资源语言正确展示。
- A：梳理资源语言字段和接口参数，在相关页面切换语言时清空依赖字段，重新请求下拉数据；在 Java Web 接口中补充按 `languageCode` 返回名称的逻辑。
- R：解决语言切换后下拉项不更新、编辑弹窗回显错误、保存参数不一致等问题。

### 案例 2：众包澳门基本学力不展示

- S：众包标注、审核、校对页面中，澳门题目需要展示基本学力第一/第二语言，但部分页面没有显示。
- T：定位基本学力显示条件，修复多流程中白名单和组件展示不一致的问题。
- A：排查 `getTaskDetail`、`getPkgVos`、`questionRule.whitelist`、`workItemSet` 和题目编辑器白名单之间的关系，分别处理标注、审核、校对、纠错和详情页的显示逻辑。
- R：澳门众包题目在加工和审核链路中能够正确展示基本学力信息，减少人工审核时的信息缺失。

### 案例 3：澳门多语言参数链路贯通

- S：任务加工页包含多个子流程，每个流程又依赖题目编辑器、题目展示、对比组件和 API 数据源。
- T：统一澳门业务来源和资源语言的传递方式，避免每个页面重复写判断。
- A：抽象 `macaoParams`，从任务包信息中解析资源语言、知识点标签、区域编码等参数，并在顶层任务页向子流程和公共组件透传。
- R：提高多语言适配的一致性，减少新增页面漏传语言参数的风险。

### 案例 4：富文本公式展示兼容

- S：题库历史数据中既有图片公式，也有 LaTeX 和 Wiris 公式，部分公式在 MathJax 渲染时失败。
- T：提升公式展示稳定性，避免题目内容丢失或样式错乱。
- A：将可识别的 `data-latex` 转换为 MathJax 公式，无法识别或特殊公式保留图片展示，并增加渲染重试和错误兜底。
- R：公式、图片和富文本在题目展示、基本学力和编辑场景中更稳定。

### 案例 5：国际化长文本布局

- S：英文、葡文资源名和教辅别名比中文长，导入弹窗和表格中出现文本溢出。
- T：修复多语言文本导致的页面撑开、按钮挤压、标签不换行问题。
- A：按文本类型制定省略、换行、断词策略，优先治理上传/导入、任务列表、表格标签等高频组件。
- R：提升多语言场景下页面可用性，降低后续页面逐点修补成本。

## 7. 面试讲法

### 7.1 30 秒版本

我做的是讯飞智学网澳门市场的国际化改造，核心不是翻译页面，而是让原来服务大陆业务的题库和资源加工系统支持澳门业务规则。澳门场景增加了资源语言、澳门题型、基本学力第一/第二语言、澳门知识点等维度，我主要负责把这些参数贯通到资源管理、众包加工、题目展示、导入导出和部分后端接口中，同时保证大陆业务不受影响。

### 7.2 1 分钟版本

这个项目涉及多个老系统，包括 Vue2 的资源加工平台、题库管理页面、专题教材管理，也有 Angular 和 Java Web 遗留系统。我的主要工作是做澳门多语言和业务规则适配，比如资源语言切换后要重新加载版本、册别、出版社、题型、试题来源；众包流程里要根据澳门业务来源展示基本学力、澳门知识点和题型；题目内容里还要处理 CKEditor、Wiris、LaTeX、MathJax 等富文本公式兼容。难点在于这些逻辑跨很多页面和公共组件，不能只在单页面写判断，所以我通过 `macaoParams` 和公共工具把业务来源、资源语言、知识点标签等参数统一传递，减少漏传和重复判断。

### 7.3 追问“你做得最有技术含量的点”

可以讲 `macaoParams` 链路：

项目里澳门判断入口很多，任务、资源包、工作室都可能携带业务来源和语言字段。早期如果每个页面自己判断，很容易出现某个子流程题型对了，但题目展示或解析对比没带语言参数。我做的处理是把澳门相关信息抽成统一参数，包括是否澳门、资源语言、知识点标签、区域编码等，然后从任务顶层向标注、审核、校对、纠错、题目编辑器、题目展示组件透传。这样后续新增页面时只需要遵守统一传参约定，不需要重新理解每个字段。

### 7.4 追问“你怎么保证不影响原业务”

可以讲数据隔离：

我没有把默认接口行为改成澳门逻辑，而是通过业务来源和资源语言参数显式触发澳门分支。比如专题、教材、目录、题型接口只有在澳门业务来源或澳门工作室下才传 `isMacao`、`isMacaoStudio`、`languageCode`，非澳门场景保持原参数和默认数据。同时自测时会把非澳门业务作为回归项，验证按钮显隐、下拉数据、编辑保存和详情回显没有变化。

## 8. 简历中不建议写死的内容

- 不建议直接写“10 万行代码”，因为统计中包含静态资源、依赖和构建文件。
- 不建议写“独立负责整个澳门项目”，除非你确认实际角色就是模块 owner。
- 不建议写“负责上线发布 / 灰度 / A/B 测试”，除非你确实参与了发布流程。
- 不建议写“从 0 到 1 搭建国际化系统”，项目更准确是“在遗留系统中做国际化和业务规则适配”。
- 不建议写“精通 Angular / Java 后端”，可以写“参与 Angular / Java Web 遗留系统适配”，除非你后续还有更多证据。
