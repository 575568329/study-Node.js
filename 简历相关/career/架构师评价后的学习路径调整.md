# 架构师评价后的学习路径调整

更新时间：2026-05-06

## 总结

架构师评价对学习路径有直接影响。当前不能再按“看到什么热词就学什么”的方式推进，而要围绕目标岗位画像补齐可讲闭环。

新的主定位：

**全栈型前端工程师 / AI 应用方向前端工程师**

学习目标不是把所有 AI 热词写进简历，而是让自己能把一个 AI 应用从需求、页面、接口、文档处理、检索、流式回答、验证和演示完整讲清楚。

## 当前最大问题

### 1. AI 方向基础还不够闭环

已经有 `rag-docs-assistant`，但还需要补：

- 稳定演示。
- 架构图。
- 3 分钟讲稿。
- 面试追问清单。
- 错误处理、日志、状态展示。
- 为什么这样做，而不只是代码能跑。

### 2. Node.js 后端深度不足

你不需要马上学高并发、微服务、分布式，但需要掌握 AI 应用后端常见能力：

- API Route / RESTful API。
- 文件上传和解析。
- SSE / WebSocket。
- 错误处理。
- 日志。
- 简单鉴权。
- 本地或数据库持久化。
- 任务状态管理。

### 3. 前端优势还没有沉淀成组件体系

不能只写“会 Vue / React”，需要能讲组件分层和复用：

- 原子组件。
- 通用组件。
- 业务组件。
- 表格、上传、筛选、弹窗、富文本、图谱节点详情等组件。
- 组件 API 设计。
- 组件文档或 Storybook。

### 4. AI 热词暂时不要铺太多

MCP、OpenClaw、LangGraph、多 Agent 可以学，但不能现在写进正式简历主能力。因为一旦写进去，面试官会要求你讲架构价值、落地范式和项目使用。

## 新学习优先级

### 第一优先级：打磨 `rag-docs-assistant`

目标：

把它从“能跑的个人项目”打磨成“能面试演示的 AI 应用项目”。

必须补齐：

- README 项目亮点。
- 项目架构图。
- 上传 -> 解析 -> 切片 -> 向量化 -> 检索 -> Prompt -> 流式回答 -> 来源引用流程图。
- 3 个稳定演示文档。
- 3-5 个稳定演示问题。
- RAG 项目 3 分钟讲稿。
- 常见追问回答。

重点讲清楚：

- 为什么要切片。
- chunkSize 和 overlap 怎么考虑。
- 为什么要做混合检索。
- 来源引用如何对应文档片段。
- 知识库没命中时如何避免模型胡说。
- 图谱抽取为什么异步做。
- 本地 FileStore 和 Chroma 的取舍。

暂不优先：

- 多租户。
- 大规模并发。
- 云原生部署。
- 复杂权限系统。

## 第二优先级：Node.js / AI 应用后端基础

目标：

让 Node.js 全栈 AI 版能经得起基础后端追问。

需要补：

- Node.js 请求处理流程。
- Next.js API Route。
- RESTful API 设计。
- 文件上传和 FormData。
- 文档解析任务状态。
- SSE 流式响应。
- WebSocket 和 SSE 的区别。
- 错误处理中间件思想。
- 日志记录。
- 简单 JWT / session 鉴权。
- 本地 JSON、SQLite、PostgreSQL 的取舍。
- 队列思想：上传后异步解析、重试、失败状态。

需要能类比理解：

- Java Bean 是什么。
- Spring IoC 是什么。
- Node.js 中如何用模块、服务类、依赖注入思想组织代码。
- MQ 的作用是什么，Node.js 里如何用任务队列思想落地。

暂不优先：

- 微服务。
- 高并发架构。
- Kubernetes。
- 分布式事务。
- 服务治理。

## 第三优先级：前端组件化沉淀

目标：

把多年业务前端经验沉淀成“我能设计组件体系”的表达。

建议做一个小型组件沉淀项目，或者在 `rag-docs-assistant` 中整理组件体系。

可以沉淀的组件：

- Button / Input / Modal 等原子组件。
- UploadPanel 上传组件。
- DataTable 表格组件。
- FilterBar 筛选组件。
- SourceCard 来源引用组件。
- GraphNodeDetail 图谱节点详情组件。
- RichTextFormulaViewer 富文本公式展示组件。
- WebSocket / SSE 状态展示组件。

需要讲清楚：

- 原子组件、通用组件、业务组件怎么分。
- 组件 props 怎么设计。
- 组件状态在哪里维护。
- 什么时候抽组件，什么时候不抽。
- 如何避免组件过度封装。

后续可选：

- Storybook。
- 组件文档页。
- 单元测试。
- npm 私有包发布流程。

## 第四优先级：AI Agent / MCP / LangGraph

目标：

等 RAG 和 Node.js 基础稳定后，再扩展到 Agent 能力。

学习顺序：

1. Tool Calling。
2. MCP。
3. LangGraph。
4. 多 Agent。
5. OpenClaw / Devin 类自动化工程体系。

每个方向都要回答：

- 它解决什么问题？
- 和普通函数调用有什么区别？
- 适合什么业务场景？
- 在项目里怎么落地？
- 失败和越权怎么控制？

暂时不要写进正式简历：

- MCP。
- OpenClaw。
- LangGraph。
- 多 Agent。

除非后续有项目、讲稿或 demo 支撑。

## 近期 4 周执行计划

### 第 1 周：RAG 项目可演示

任务：

- 整理 README。
- 准备演示文档。
- 固定 3-5 个演示问题。
- 确保上传、问答、来源引用、图谱能稳定展示。

产出：

- 可演示项目。
- README。
- 演示步骤。

### 第 2 周：RAG 架构和讲稿

任务：

- 画架构图。
- 写 3 分钟项目讲稿。
- 写 10 个追问答案。

产出：

- 架构图。
- 3 分钟讲稿。
- 面试追问清单。

### 第 3 周：Node.js 后端基础补强

任务：

- 梳理 API Route。
- 补错误处理和日志。
- 学 SSE / WebSocket 区别。
- 理解文件上传、任务状态、失败重试。

产出：

- Node.js 后端追问笔记。
- RAG 项目错误处理优化。

### 第 4 周：组件化沉淀

任务：

- 整理 `rag-docs-assistant` 组件结构。
- 抽出 3-5 个可讲组件。
- 写组件分层说明。

产出：

- 组件沉淀文档。
- 组件设计讲稿。

## 简历同步规则

可以写进简历：

- RAG。
- SSE 流式响应。
- 混合检索。
- 来源引用。
- 文档解析。
- 文件上传。
- 知识图谱。
- Node.js / Next.js API Route。
- 组件化沉淀。

暂时不要写进简历：

- MCP。
- OpenClaw。
- LangGraph。
- 多 Agent。
- 高并发。
- 微服务。
- 分布式。
- Kubernetes。

写入条件：

只有当某项能力满足以下条件，才写进简历：

1. 有项目代码。
2. 有演示或截图。
3. 能讲 3-5 分钟。
4. 能回答 5 个以上追问。
5. 能说明为什么这样设计。

## 最终判断

接下来学习的核心不是“更多关键词”，而是：

**围绕全栈型前端 + AI 应用交付，把 RAG 项目、Node.js 后端基础、前端组件化和面试表达打磨成闭环。**

MCP、LangGraph、OpenClaw 可以学，但必须放在 RAG 项目闭环之后。
