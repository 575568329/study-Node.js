# 网页简历三版本方案审阅稿

更新时间：2026-05-05

当前状态：已根据调研结论和资深 AI 公司面试官视角，重写并落地到 React 网页简历项目。

补充状态：已阅读架构师评价，并按“强化定位、避免夸大、保证可讲”的原则完成一轮保守落地。

## 目标

用 React 网页方式维护 3 个简历版本，再通过浏览器打印保存为 PDF。简历允许有颜色、层次和前端工程师特征，但核心仍然是招聘筛选效率：HR 能快速判断匹配度，技术面能看到项目深度。

最终只保留 3 个版本：

1. 通用版
2. 纯前端版
3. Node.js 全栈 AI 版

不再单独做 GIS 可视化版、教育国际化版、独立 AI 应用前端版。GIS 和教育项目仍可作为项目经历使用，但它们不作为单独求职方向。

## 1. 通用版

目标岗位：

- 前端开发工程师
- React / Vue 前端工程师
- B 端系统前端
- 对 AI 有加分但不是硬要求的前端岗位

主标题建议：

**前端开发工程师｜Vue / React / TypeScript｜AI 应用实践**

核心定位：

通用版用于大多数投递场景，强调你是一个有 5-6 年复杂业务系统经验的前端开发，同时具备 Next.js / RAG 项目实践。它不把你包装成纯 AI 工程师，也不把方向缩窄到 GIS 或教育行业。

核心卖点：

- 5-6 年前端开发经验。
- 有复杂 B 端、教育出海、GIS 可视化、IoT 车载终端经验。
- 熟悉 Vue2 / Vue3，同时具备 React / Next.js 项目实践。
- 有 `rag-docs-assistant` 作为 AI 应用项目，能体现技术更新和差异化。

项目排序：

1. 讯飞智学网澳门市场资源加工与题库国际化改造
2. 智能知识管理平台 / RAG 文档问答系统
3. 甘肃 / 北京地质灾害 GIS 可视化项目

内容侧重：

- 工作经历保留完整时间线。
- 项目经历覆盖“真实工作复杂度 + AI 项目 + 可视化性能优化”。
- RAG 项目写到可证明能力即可，不喧宾夺主。

页面风格：

- 稳重、清晰、带一点现代感。
- 主色建议：统一深蓝 + 蓝灰。
- 适合做默认打开版本。

适合投递：

- 不确定岗位偏好的场景。
- 普通前端岗位。
- 外包、行业软件、B 端系统、小中型互联网公司。

## 2. 纯前端版

目标岗位：

- 前端开发工程师
- Vue 前端工程师
- React 前端工程师
- B 端系统前端

主标题建议：

**前端开发工程师｜Vue / React / TypeScript｜复杂业务系统 / 可视化 / 国际化**

核心定位：

纯前端版用于稳定投递。它重点证明你能做真实业务系统交付，而不是只会个人项目或 AI 工具。AI 项目不作为主线，最多作为补充能力。

核心卖点：

- Vue2 / Vue3 和传统 B 端系统经验扎实。
- 能处理遗留系统、跨系统参数链路、富文本公式、WebSocket、地图可视化等复杂问题。
- 有上线、页面路径验证、客户现场支持、系统迁移等真实交付经历。

项目排序：

1. 讯飞智学网澳门市场资源加工与题库国际化改造
2. 甘肃 / 北京地质灾害 GIS 可视化项目
3. 上汽车载终端实时数据与跨端项目

内容侧重：

- 强调 Vue、React、TypeScript、Webpack、Vite、OpenLayers、ECharts、WebSocket。
- 讯飞项目突出多系统、国际化、富文本公式、题库流程。
- 地灾项目突出 8000 点位、OpenLayers、首页加载提升 50%。
- 车载项目突出 10 万+ WebSocket 数据、uni-app、小程序、JS-Bridge。

页面风格：

- 工程化、清爽、信息密度高。
- 主色建议：统一深蓝 + 蓝灰。
- 少用装饰，突出经历和项目。

适合投递：

- 大多数前端岗位。
- 武汉本地 B 端、行业软件、外包、传统互联网前端岗位。

## 3. Node.js 全栈 AI 版

目标岗位：

- 全栈型前端工程师
- Next.js 工程师
- Node.js + React 工程师
- AI 应用全栈前端
- RAG / 企业知识库应用工程师

主标题建议：

**全栈型前端工程师｜React / Next.js / Node.js｜AI 应用方向**

核心定位：

这个版本是差异化版本，用于投 AI 应用、小团队全栈、Next.js 和 Node.js 相关岗位。定位不是资深后端，而是“具备复杂前端交付经验，能独立完成 AI 应用前端、API Route、文档处理、向量检索和流式问答链路的全栈型前端”。

核心卖点：

- 有真实前端复杂项目作为基本盘。
- `rag-docs-assistant` 已经实现完整 RAG 文档知识管理平台。
- 能写 Next.js App Router、API Route、文件上传、文档解析、本地持久化、向量存储抽象、AI SDK 流式接口。
- 能把 AI 能力落到可演示系统，而不是只写调用接口 demo。

项目排序：

1. 智能知识管理平台 / RAG 文档问答系统
2. 讯飞智学网澳门市场资源加工与题库国际化改造
3. 甘肃 / 北京地质灾害 GIS 可视化项目

内容侧重：

- RAG 项目写完整：多知识库、上传、解析、切片、Embedding、FileStore / Chroma、混合检索、流式问答、来源引用、知识图谱。
- 讯飞项目证明真实业务系统和复杂流程改造能力。
- 地灾项目证明可视化、性能优化和复杂数据处理能力。
- 不强行写高并发、微服务、分布式，不把自己包装成资深后端。

页面风格：

- 更偏现代产品控制台。
- 主色建议：统一深蓝 + 蓝灰。
- 可以使用轻量流程条，例如 `Upload -> Chunk -> Embedding -> Retrieve -> Stream`。
- 技术标签和项目链路可以更明显，但正式 PDF 中不要出现说明性废话。

适合投递：

- AI 创业公司。
- 小团队全栈岗位。
- Next.js / React / Node.js 岗位。
- 企业知识库、RAG、AI 助手类项目团队。

## 页面设计方案

### 总体版式

继续用 A4 页面渲染，但不强制每页固定高度截断。使用浏览器自然分页，保证内容不被裁掉。

建议结构：

1. 顶部信息区：姓名、标题、联系方式、城市。
2. 简短摘要：2-3 行，直接说明定位。
3. 技能区：每个版本 3 组技能。
4. 工作经历：通用版和纯前端版保留完整工作经历；Node.js 全栈 AI 版可以弱化工作经历，把项目提前。
5. 项目经历：每个版本放 3 个核心项目。
6. 教育经历：保持简洁。

### 颜色策略

允许使用颜色，但要服务于信息层级：

- 三个版本统一使用深蓝 + 蓝灰。
- 不再按版本切换主题色，避免导出 PDF 后显得像多套风格不一致的作品集。

颜色使用位置：

- 顶部标题线。
- 版本标签。
- 项目标题左侧色条。
- 技术标签底色。
- 小型模块标题。

不建议：

- 大面积渐变背景。
- 深色整页背景。
- 过多卡片嵌套。
- 装饰性圆球、发光背景。
- 太像作品集首页，削弱简历阅读效率。

### 前端工程师特色

可以体现“用页面写简历”的特点：

- 顶部有版本切换按钮，便于生成不同 PDF。
- 三个版本统一使用蓝色视觉，保证 PDF 投递时正式、稳定。
- 技术标签、项目模块、工作经历都组件化。
- 打印时隐藏交互控件，只保留正式简历内容。
- 可后续加打印样式检查，但这些提示不出现在 PDF 里。

正式 PDF 中不应出现：

- “可展开亮点”
- “技术关键词”
- “项目覆盖范围”
- “切换版本后用浏览器打印保存 PDF”
- 任何给自己看的说明文字

## 内容取舍原则

### 要写

- 真实工作项目。
- 可讲清楚的技术链路。
- 可验证的数据：8000 个点位、首页加载提升 50%、270+ 提交、900+ 文件变更、10 万+ WebSocket 数据。
- 已完成的 RAG 项目能力。

### 少写或不写

- 未完成的计划。
- 学习 demo。
- 没有把握的指标。
- “90% AI 开发”这种容易被误解的表达。
- 过度包装成资深 AI 工程师、资深后端工程师。

## 资深 AI 公司面试官视角审阅

假设我是一个有 20 年经验、现在在互联网 AI 应用公司负责前端 / 全栈招聘的面试官，我对当前方案的判断是：

**方向判断是对的，但表达还需要更锋利。**

当前就业形势不是“前端没有机会”，而是普通页面型前端竞争变大。更有竞争力的是：

- 能做复杂业务系统的人。
- 能处理端到端交付的人。
- 能用 React / Next.js / Node.js 做 AI 应用的人。
- 能把 AI 生成代码审查、验证并稳定交付的人。

你当前素材里，真正有价值的是：

- 真实复杂项目：讯飞、地灾、车载。
- 可验证数据：270+ 提交、900+ 文件变更、8000 点位、首页加载提升 50%、10 万+ WebSocket 数据。
- 新增长曲线：`rag-docs-assistant` 已经是一个可讲 RAG 链路的项目。

### 面试官评分

当前如果按 10 分评估：

| 维度 | 评分 | 评价 |
| --- | --- | --- |
| 方向选择 | 8 / 10 | 三版本聚焦合理，比多方向维护更稳 |
| 项目素材质量 | 7.5 / 10 | 真实项目够用，但还需要更清晰的结果表达 |
| AI 差异化潜力 | 8 / 10 | RAG 项目方向对，但需要演示、架构图和讲稿支撑 |
| 当前简历成熟度 | 6.5 / 10 | 内容有了，视觉和表达还需要压缩、排序、强化 |
| 面试可讲性 | 6.5-7 / 10 | 取决于 RAG 项目能否讲清楚和现场演示 |

### 最大优势

1. 不是只有学习项目，有真实工作经历托底。
2. 讯飞项目足够复杂，能证明跨系统、遗留系统、国际化、富文本公式能力。
3. 地灾项目有规模和性能数据，能证明复杂数据可视化能力。
4. 车载项目能证明实时数据和跨端能力。
5. RAG 项目能把你从“传统前端”拉到“AI 应用前端 / 全栈型前端”。

### 最大风险

1. **RAG 项目如果没有可运行演示，会被当成学习 demo。**

必须准备：

- 可运行项目。
- README。
- 架构图。
- 3 个稳定演示问题。
- 1 组演示文档。
- 截图或录屏。

2. **AI 辅助开发表达容易翻车。**

不要写：

- 90% AI 开发。
- 代码主要由 AI 完成。
- AI 替代了开发。

建议写：

- 深度使用 AI 辅助需求拆解、代码生成、问题定位和回归验证。
- 个人负责方案判断、代码审查、业务验证和最终质量把控。

3. **Node.js 全栈 AI 版容易被追问后端深度。**

可以讲：

- Next.js API Route。
- 文件上传。
- 文档解析。
- 本地 JSON 持久化。
- 向量存储抽象。
- RAG 检索链路。
- 流式接口。

不要主动讲：

- 高并发。
- 微服务。
- 分布式。
- 复杂数据库调优。
- 云原生运维。

4. **网页简历如果设计过度，会降低正式感。**

可以有颜色和组件化，但最终 PDF 必须像正式简历，不像作品集首页。

## RAG 项目面试追问清单

Node.js 全栈 AI 版一定会被追问 `rag-docs-assistant`。你需要能回答：

1. 文档上传后的完整处理链路是什么？
2. `.pdf`、`.docx`、`.xlsx` 分别如何解析？
3. chunk 策略为什么这样设计？chunkSize 和 overlap 怎么定？
4. embedding 调用失败怎么处理？
5. FileStore 和 Chroma 的接口怎么抽象？
6. 为什么要做混合检索？关键词和向量检索如何结合？
7. Top-K 为什么取这个数量？
8. 来源引用如何和回答内容对应？
9. 知识库没有相关内容时如何避免模型胡说？
10. 知识图谱实体抽取是同步还是异步？失败是否影响上传？
11. 本地 JSON 持久化的优缺点是什么？
12. 如果上线给多人使用，下一步会如何改造？

这些问题如果能讲清楚，Node.js 全栈 AI 版就有竞争力。讲不清楚，这个版本会变成风险点。

## 三版本审阅结论

### 通用版

评价：最适合默认投递。

原因：

- 稳定。
- 不过度包装。
- 工作经历完整。
- 有 RAG 项目作为加分项。

建议：

- 简历标题不要太 AI 化。
- RAG 项目放第二或第三，不要压过真实工作经历。
- 摘要里强调“复杂业务系统 + AI 应用实践”。

### 纯前端版

评价：必须保留，是保底转化版本。

原因：

- 你的工作经历主线仍然是前端。
- 当前市场仍需要 React / Vue / TypeScript / 工程化 / B 端系统能力。
- 这个版本最容易通过传统岗位筛选。

建议：

- 不要让 AI 项目抢主线。
- 重点突出讯飞、地灾、车载三个真实项目。
- 技能区以 Vue / React / TypeScript / OpenLayers / ECharts / WebSocket 为主。

### Node.js 全栈 AI 版

评价：最有潜力，但必须控制边界。

原因：

- AI 应用公司、小团队、Next.js 岗位确实需要这类人。
- `rag-docs-assistant` 能支撑你的差异化。
- 但你的后端深度还不能写得太满。

建议：

- 标题用“全栈型前端工程师”，不要用“资深全栈工程师”。
- 项目第一位放 RAG。
- 后端能力写 API Route、文件处理、向量存储、流式问答。
- 不写高并发、微服务、分布式。

## 落地验收标准

这三个版本真正可投递前，需要满足：

1. 每个版本都有清晰标题，3 秒内能看出岗位方向。
2. 每个版本项目排序不同，且服务于对应方向。
3. 每个项目 bullet 都以“动作 + 技术/业务对象 + 结果”组织。
4. PDF 不截断、不出现页面控件、不出现给自己看的说明。
5. RAG 项目有 README、架构图、演示数据、截图或录屏。
6. Node.js 全栈 AI 版不夸大后端深度。
7. AI 辅助研发表达强调审查和质量，不强调代码由 AI 生成比例。
