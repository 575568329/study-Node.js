## 简历主项目 1：智能知识管理平台 / RAG 文档问答系统

### 推荐定位

面向个人或小团队的 RAG 文档知识管理平台，围绕知识库管理、AI 问答、知识图谱三个工作区组织。项目支持多知识库、文档上传解析、文本切片、Embedding 向量化、混合检索、流式问答、来源引用和知识图谱展示。

### 可写技术栈

`Next.js App Router`、`React`、`TypeScript`、`Tailwind CSS`、`AI SDK`、`GLM-4-flash`、`embedding-3`、`pdfjs-dist`、`mammoth`、`exceljs`、`FileStore / ChromaDB`、`graphology`、`react-force-graph-2d`

### 目前已有依据

- `rag-docs-assistant` 已实现 Next.js App Router 工作台，包含数据页、对话页、图谱页。
- 支持创建、删除、选择多知识库，并通过 `kbId` 保持知识库选择、文档状态、对话上下文和图谱视图同步。
- 支持上传 `.txt`、`.md`、`.pdf`、`.docx`、`.xlsx` 文档，包含文件大小校验、同名去重、文本解析、切片、向量化和元数据记录。
- 默认使用本地 JSON FileStore 持久化向量数据，保留 ChromaDB 切换能力。
- RAG 对话接口已实现 GLM embedding-3 查询向量化、混合检索 Top-K、上下文注入、GLM-4-flash 流式回答和来源引用。
- 文档上传后异步抽取实体和关系，写入知识图谱；图谱页支持节点、关系、搜索、收藏和节点详情。

### 简历项目描述草稿

**智能知识管理平台 / RAG 文档问答系统｜Next.js + TypeScript + AI SDK**

- 基于 Next.js App Router 搭建数据、对话、图谱三工作区，通过 `kbId` 保持知识库选择、文档状态、对话上下文和图谱视图同步。
- 实现多知识库创建、删除、选择与状态刷新，支持 `.txt`、`.md`、`.pdf`、`.docx`、`.xlsx` 文档上传，完成文件校验、同名去重、文本解析和处理状态展示。
- 设计文档切片与向量化链路，按标题分段结合固定窗口切片，批量调用 GLM embedding-3，并保存文档、切片和来源元数据。
- 抽象向量存储接口，默认使用本地 JSON FileStore 持久化向量数据，同时保留 ChromaDB 切换能力，支持向量写入、相似度检索和集合删除。
- 实现 RAG 流式问答接口，将最近对话历史拼接为检索查询，结合向量相似度与关键词混合检索 Top-K 片段，并通过 AI SDK 接入 GLM-4-flash 生成回答。
- 在回答中透出来源引用、文件名、章节和相关性分数；当知识库无相关内容时明确标注为 AI 补充回答，降低回答与资料混淆风险。
- 接入实体关系抽取和知识图谱能力，文档上传后异步生成文档节点、实体节点和关系边，图谱页支持节点数量、关系状态、搜索、收藏和节点详情查看。

### 需要补强

- 补一张架构图：上传解析 -> 切片 -> Embedding -> FileStore / Chroma -> 混合检索 -> Prompt -> LLM Streaming -> 来源引用。
- 准备 2-3 个演示文档和一组稳定问题，保证面试现场可以展示上传、问答、来源引用和图谱效果。
- 后续可补登录鉴权、团队协作空间、在线部署数据存储和自动化测试；这些未完成能力不要写进正式简历。

## 简历项目 2：任务管理系统

### 推荐定位

前端工程化项目，体现 React / Next.js / TypeScript 的业务开发能力，可作为从 Vue2 迁移到现代 React 技术栈的证明。

### 可写技术栈

`React`、`Next.js`、`TypeScript`、`React Router`、`TanStack Query`、`Zustand`、`React Hook Form`、`Zod`、`Tailwind CSS`

### 目前已有依据

- React 版本包含登录路由守卫、任务列表、标签管理、个人中心。
- 任务模块包含增删改查、搜索、状态筛选、优先级筛选、弹窗编辑。
- 使用 TanStack Query 封装任务请求和缓存失效。
- 使用 Zustand 管理登录态和 token 持久化。
- Next.js 版本包含 App Router、API Route、服务端获取数据和客户端交互组合。

### 简历项目描述草稿

**任务管理系统｜React / Next.js + TypeScript**

- 使用 React Router 设计登录页、任务列表、标签管理、个人中心等页面，并实现基于 token 的前端路由守卫。
- 基于 TanStack Query 封装任务增删改查请求，通过 `invalidateQueries` 保证列表数据在变更后的自动刷新。
- 使用 Zustand 管理登录状态和 token 持久化，拆分 API 请求、类型定义、Hooks、页面组件，提升代码可维护性。
- 在 Next.js 版本中实践 App Router、API Route、服务端数据获取和客户端组件交互，为后续迁移全栈框架打基础。

### 需要补强

- README 还是 Vite 默认模板，需要改成项目说明。
- 需要补登录表单校验、错误态、空态、loading 态截图。
- 如果写进简历，建议合并表述为“任务管理系统”，不要同时写 React 版和 Next.js 版两个项目。

## 简历项目 3：Node.js 个人博客 API

### 推荐定位

后端 RESTful API 项目，体现 Node.js、Express、MySQL、Sequelize、JWT、文件上传和安全设计能力。

### 可写技术栈

`Node.js`、`Express`、`MySQL`、`Sequelize`、`JWT`、`bcrypt`、`Multer`、`Helmet`、`express-validator`

### 目前已有依据

- 已有用户注册/登录、JWT 鉴权、文章列表/详情/创建/编辑/删除、评论、上传等模块目录。
- 数据库 schema 包含用户、文章、评论、上传文件表，并设置外键和常用索引。
- API 设计文档覆盖公开接口、认证接口、用户模块、文章模块、评论模块和文件模块。

### 简历项目描述草稿

**个人博客 RESTful API｜Node.js + Express + MySQL**

- 基于 Express 设计用户、文章、评论、上传等 RESTful API 模块，按 router、controller、middleware、model 分层组织代码。
- 使用 JWT 实现无状态认证，结合 bcrypt 对用户密码加密存储，并通过鉴权中间件保护文章发布、编辑、删除等接口。
- 使用 Sequelize 建模用户、文章、评论、上传文件等表关系，设计外键约束和常用索引，支持文章分页查询、作者关联查询和浏览次数统计。
- 接入 Helmet、CORS、速率限制、参数校验和统一错误处理中间件，补齐基础安全与工程化能力。

### 需要补强

- 代码里仍有不少 TODO 注释，写简历前建议清理或改成正常实现注释。
- `deletePost` 缺少文章不存在判断，面试前最好修。
- README 的“待实现功能”和 API-DESIGN 的“已完成”描述存在不一致，需要统一。
- 缺少测试脚本，至少补 Postman 集合或接口测试说明。
